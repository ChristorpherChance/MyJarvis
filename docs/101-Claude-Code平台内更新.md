## 范围与当前边界

**2026-10-21 开发状态：部分实现、未发布。** 平台API／界面已通过隔离流程验证，普通账号本地合成包目录交换测试通过；维护guard的真实runner接入证明未完成，专项测试出现失败及超时，不能宣称生产可用。节点 `validate_runner_guard` 明确拒绝实际激活，`guardReady=false`；后台worker、安装器和完整故障恢复仍需端到端复验。本轮只保留独立候选，不把未验runner改动同步常规源码，不连接或修改101。下文是已设计的使用流程和边界，不表示现在已经可以在正式平台执行。

本功能将 Claude Code 软件版本维护与“配置 AI 开发环境”“切换终端模型”分开。入口为“运维费用 → AI开发环境”，也可在101机器详情的同名页签进入。首版只支持可信绑定的101普通账号 `superopen`、经过节点重新核实的 Linux x64 glibc npm 安装布局。

**开发代码存在不等于生产功能已发布，更不等于101已经升级。** 实际接入、部署、检查和更新均以各阶段真实回执为准。101旧采集与CC Switch桥接不赋予软件修改权限；未安装受信更新组件、未接入维护保护或来源不可核实时，更新保持阻断。

101历史执行器直接引用：

```text
/home/superopen/opt/node22/lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe
```

该 `.exe` 后缀不能判断为Windows程序。节点检查文件类型、包版本及实际直接入口，不仅检查交互终端PATH。10月10日和10月17日历史证据记录2.1.296，不能代替今天的节点检查。

## 日常操作

1. 在机器选择器核对101，点击独立“Claude Code更新”区域的“检查版本”。
2. 查看检查时点、实际版本、npm布局、安装指纹及维护保护状态。过期观察不作为更新前置。
3. 从服务提供的可信发行目录选择明确版本，生成更新预览。预览冻结旧安装指纹、目标版本、来源及有效期，不在确认后偷偷跟随latest。
4. 核对“将101的Claude Code从X更新至Y”的确认文本和维护影响，然后确认执行。生成预览本身不安装任何软件。
5. 等待持久回执。排队、运行或下载完成不是更新完成；只有原工厂入口实际版本、安装树、维护保护与配置不变性核验均通过，才记为成功。

已有工厂任务不会被终止。维护保护繁忙时更新拒绝，不取消任务、不重启服务，不开启101冷备或工厂全局监督。终端有未受共同锁保护的CLI进程时同样应阻断激活。

## 固定来源与完整性

`scripts/ai-development/claude-code-catalog.mjs` 只从固定npm官方registry读取发布标签和两个精确同版本包的元数据：

- `@anthropic-ai/claude-code`；
- `@anthropic-ai/claude-code-linux-x64`。

可使用 `stable`（默认）、`latest` 或明确正式版本生成待审核的目录快照。标签在检查时解析为具体版本；目录需由受信安装流程固定到中央与节点，不接受浏览器提交的地址、包名、路径或命令。

```bash
node scripts/ai-development/claude-code-catalog.mjs stable
```

该命令只输出元数据，不安装、不激活、不修改节点配置。实际目录分发按专用安装器的预检和明确执行模式操作，不将命令输出直接当作已部署策略。

`sourceSha256` 是规范化发行描述符的SHA-256，绑定主包及Linux平台包的版本、来源URL、SHA-512 SRI和大小；不是伪造的包文件SHA-256。每个下载包另按官方registry提供的SHA-512完整性校验。此机制不等于已经独立验证registry签名，不声称额外供应链信任。

2026-10-21本次只读来源检查时stable为2.1.304、latest为2.1.306；这只是当时值，不写入应用常量。目标版本不高于当前版本时不升级，不自动降级。

## 部署前置

- 中央现有非特权AI开发控制器及固定运维SSH身份已经可信绑定；为更新功能配置独立policy、queue、state与发行描述符，旧provider vault不读取、不重建。
- 101安装专用root-owned固定dispatcher及模块pin，普通目标账号明确绑定。只读collector和CC Switch密钥不能改作安装通道。
- 工厂runner已实际接入同一OS维护锁协议，并能验证真实holder、PID/start身份和模块hash。仅设置一个“支持锁”的布尔值不构成接入。
- 旧runner未接入、安装类型未知、原子交换不支持、目录跨文件系统或实际使用状态不能确认时，保持禁用。

中央扩展安装器为 `scripts/ai-development/install-claude-code-update-controller.py`，默认只预检；`--execute`仅安装已审查文件与systemd drop-in，不隐式启动服务。它核对原controller/config/legacy配置指纹，保留原配置和私密vault，不接收模型认证值。安装仍是独立生产维护操作，不能由开发测试结果代替授权和现场验证。

## 结果不明与恢复

升级指令在发送前持久化，一次任务只发送一次 `start`。SSH断开或客户端超时后只查原任务 `status`，不重新发起安装。页面刷新或重复点击不能制造第二次升级。

- **成功核验**：目标版本和完整安装树已从原入口核对，保护配置未改变。
- **失败／未改变**：前置检查、下载或候选验证拒绝，没有激活。
- **已恢复**：失败后恢复原安装，并实际回读旧入口和版本；不以尝试恢复冒充成功。
- **待核实**：当前激活、回退或锁状态不能确认，保留原任务、备份和维护标记，阻止新更新／新任务领取，等待同任务对账。

开始／激活授权期限与后续观察恢复窗口分开。过期不能开始新激活，但严格绑定的晚到终态仍可核对。外部修改导致指纹漂移时不覆盖外部变化；不要手工删除pending/unresolved标记或旧包来绕过门禁。

## 隐私、费用与验收

检查和更新不发送模型prompt，不读取聊天正文，不更换认证、provider、模型映射、工厂模板或shell配置。节点只返回安全软件元数据和不变性结论；私密配置指纹留在节点，不上传配置正文。CC Switch数据库应按受保护逻辑字段核对，不能把WAL/checkpoint字节变化直接判为配置变化。

本地合成包、fake worker和隔离浏览器结果只能证明代码及合同范围，不证明101真实升级。各阶段测试、失败与修复、平台发布、节点接入和实际升级均按建设记录工具分别留证。开发过程助手与子代理的费用未知部分保持未知，不能因产品测试不调用模型便写成整体零费用。
