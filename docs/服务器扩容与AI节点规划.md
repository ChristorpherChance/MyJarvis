本页是版本化规划，不是机器在线状态。平台入口：系统运维 → 设备管理 → 服务器配置与扩容规划；需管理员登录。硬件申报与实测、规划与实际接入分开，后续内容更新随文档发布同步。

## 1. 当前结果与口径

2026-10-23，用户确认的新增机器已扩展为 **11 台**，全部通过112正式平台R58的认证机器API登记并逐台读回。前8条在补充DDR4信息时使用原UUID更新至修订2；后3条为修订1。显示名称中的“新增01～11”是规划标签，不是主机名、地址或自动分配的服务器编号。

所有资产地址和位置留空，保持 `status=unknown`、`agentStatus=not-configured`、`verification=unverified_external`，没有加入可信控制器、执行器或AI策略。`always=false`只表示本轮尚未设置常驻计划，不代表机器关机。第9台是公司只读资产；第10台经用户明确确认是个人设备。

[真实登记和读回回执](../artifacts/fleet-onboarding/registration-public.json)记录资产UUID、修订和权限边界。原始申报与字段口径见 `scripts/planned-machines-20261023.json`。本规划不是硬件实测或已部署清单。

## 3. 保持现有职责不变

- **112**：正式贾维斯与常规开发、监管中心；不复制生产家庭数据/队列到新机器跑第二个中心。
- **101**：平台冷备兼独立软件工厂节点，保持现有暂停、任务与接管边界；不因为新增资产启动冷备或终止任务。
- **116**：现有项目与模型路由职责保持。新增10是单独个人资产，“同配置”不是同身份。
- **NAS120**：存储与备份对象，公网入口保持现有独立路径；不把活跃SQLite WAL数据库放NAS共享目录，不将NAS当计算工厂。
- **广州/日本网关**：现有代理、路由和隧道职责不变，不为新机规划修改端口/认证。

新计算节点只承接经过明确授权的独立任务及工作副本。没有GPU资源池、Kubernetes或跨机模型分片的已部署承诺；先验证单机，再考虑有实际收益的编排。

## 4. 建议安装接入顺序

1. **新增03＋新增06**：一台GPU工作站、一台轻量机，先完成标准Ubuntu24桌面安装、可信接入和只读诊断验收。
2. **新增01／02**：测CPU/内存/磁盘/功耗/稳定性，按任务实际收益分配构建、测试和批处理；不默认全天常驻。
3. **新增04／05／07／08**：完善多环境、轻量/移动节点和隔离恢复用途；60GB Ubuntu环境严格控制磁盘。
4. **新增10／11**：按Windows与macOS客户端兼容环境管理，不套Linux安装器。Win10及macOS12的支持/安全更新状态、CLI依赖须专项核验。
5. **新增09**：保留公司只读清单，未经公司与用户另行授权不执行接入/修改。

所有地址在网络拓扑/DHCP确认后填写，本轮不预分配IP。新装系统使用普通账号、主机指纹核验、最小权限；不能将只读采集通道改成任意命令通道。

## 5. 标准验收清单

### 系统与硬件
- 准确CPU SKU、单/双路、核心线程、内存容量/代际；申报值与实测值分别保存。
- 磁盘SSD/HDD、健康、总量与实际可用空间；不要把型号标称容量与系统可见容量混算。
- GPU准确型号、独立/共享显存、驱动、CUDA/其他运行时支持和实际设备可见性；老GPU不自动套新驱动栈。
- Ethernet/Wi-Fi、带宽、时钟、温度、持续负载；功耗仪或可信采样后再决定常驻。
- 笔记本休眠/电池/合盖策略；虚拟环境的vCPU、分配磁盘/内存和GPU直通/共享关系。

### 资产更新和信任接入
- 给实物贴规划标签，读取原UUID和最新修订；用完整机器update合同合并更新，遇409重新核对，禁止删除重建。
- 资产登记、OS已装、Agent已配、可信在线、配置符合、真实任务验收分别记录。
- 注册本身不授权远程执行。可信策略绑定资产UUID、实际地址、普通账号、主机指纹与允许动作。
- 不复制其他机器的SSH私钥、machine-id、Agent密钥或数据库。公开记录不含凭据。

### AI工具与配置
- Linux、Windows、macOS分别评估支持条件；当前固定Linux模板不是跨平台通用安装器。
- 模型通道、角色映射、默认选择、状态栏与上下文/压缩策略属于版本化配置目标；认证、安全权限和hooks默认不在自动收敛范围。
- 先只读差异预览，再对明确单机应用；付费推理验证需另行明确，不能为补记录自动调用模型。
- 配置匹配不等于终端已加载，实际界面与调用验收单列。前轮CLI升级仍有独立维护保护阻塞，不因本批登记放行。

## 6. 本轮统一配置建设的交付边界

本轮实现状态栏只读分层诊断候选：脚本、全局、common、当前provider及各provider计数，结果只含枚举/计数，不上传设置值、命令或私密路径。旧协议显示未观测，不造匹配；不可读不造缺失；零provider不造全部配置通过。

后续动态可信节点、模板preview/apply、第二台真实配置与干净新机验收分别推进。源码验证不是生产发布，未更新节点模块前不宣称已定位112真实不一致原因。11台占位已真实落平台，系统安装、节点接入、统一配置和调度仍未做。
