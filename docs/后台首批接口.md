# 贾维斯 · 后台首批接口

2026-10-05。第一批真实接口已经落地：统一收件、灵感研究、项目管理、任务交付、经验技能。完整演示继续用于对照，新增真实工作台用于录入与联调。

## 现在怎样使用

打开 `http://127.0.0.1:3140/?mode=api`，使用原管理员账号。首次安装时才建立密码；已有账号无需重新设置。真实库从实际记录开始，演示空间保留原型样例。

1. 在统一收件记录原话，选择资料范围；整理后归档为研究或经验。
2. 经验填写适用条件与核验依据，验证后发布技能；新版正文重新核验，旧任务固定引用旧版本。
3. 研究补充问题、证据与方案；本人决定采纳后转项目，保留研究来源。
4. 项目登记设备上的工作副本与里程碑；可以生成有先后依赖的排队任务。
5. 开发在平台之外完成时，手工提交有来源的进度与产物声明；本人独立验收后形成固定交付版本。

后台仍以 Pi SDK 为智能基础。原 Pi 对话保留真实会话、增量回答、停止与模型配置；查询工具已能读取新旧两批项目、任务和经验。业务状态由接口规则决定，模型回答不会直接批准交付或部署。

## 运行与存储

联想 64GB 继续作为开发测试环境，服务仍只监听 `127.0.0.1:3140`。本次没有更改其他机器或进行生产部署。

2026-10-05 15:32 已更新本机服务，并确认健康检查、原账号存在、V1 认证和前端访问正常。切换前备份位于 `artifacts/backups/backend-v1-20261005-153200`；启动核验见 `artifacts/v1-api-qa/deployment.json`。

数据库为 `.jarvis/jarvis.db`；V1 使用 `v1_documents`、`v1_commands`、`v1_events` 和版本元数据表。原台账、管理员凭证、登录记录与会话索引保留。现有备份工具的数据库快照包含 V1 表，Pi 专用目录仍按原方式备份。

开发仍用 `npm run dev`，构建 `npm run build`，运行 `npm start`。后台验收为 `npm test`，真实工作台临时库验收为 `node_modules/.bin/tsx scripts/qa-v1-runtime.ts`；后者独立创建与清理临时库，不向 3140 写测试记录。

单次请求最多 128 KiB，超限会明确提示缩减内容；大量记录分批登记。书籍扫描件上传将在知识模块单独实现。

## 这批完成的底座

| 能力 | 行为 |
| --- | --- |
| 身份和资料范围 | 所有者来自服务端会话，拒绝跨所有者或范围联动 |
| 重复提交 | 同提交编号返回同回执，响应丢失后可安全重试 |
| 并发写入 | 旧 revision 拒绝覆盖新记录 |
| 原子保存 | 关联记录、事件与回执统一提交，任何失败统一回滚 |
| 接口契约 | 严格输入和输出检查，原有 S0 协议继续兼容 |
| 修订与出处 | 原话、审阅、人工报告及版本引用可以回查 |
| 实时与恢复 | 持久化事件续订、会话退出、服务关闭、备份恢复 |
