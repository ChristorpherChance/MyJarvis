## 2 R53实际改了哪些模块和接口

源码路径均相对于上述R53源码副本。R53扩展了既有工作台返回和模型输入，没有新增可绕过授权的派发端点。

| 源码 | 接手时应理解的职责 |
| --- | --- |
| `apps/api/src/runtime/supervisor-evidence-history.ts` | 沿受控运行的`consumedRunId/resultHash`构建同目标原件连续链；保每件来源与完整字节，冲突或陈旧绑定拒绝 |
| `apps/api/src/runtime/project-supervisor-runtime.ts` | 将统一原件并集、证据表和引用白名单冻结到新model intent；模型前、决定应用前及后继派发前重新核对，不改旧回包或重调旧intent |
| `apps/api/src/runtime/supervisor-model-input.ts` | 在模型序列化时去除可严格重建的重复审计字段；完整冻结输入仍保存，完整prompt仍受131072 UTF-8字节门约束 |
| `apps/api/src/runtime/project-supervisor-contract.ts` | 保严格六键、逐字标准、全met与引用门；澄清transport不等于历史作者身份，不追加无关标准或重复授权要求 |
| `apps/api/src/runtime/project-workbench-runtime.ts` | 只读生成`currentLoopBrief`，优先展示当前绑定回包、主管判断和下一步；自动形成有限本轮回报，不写任务完成或独立验收 |
| `apps/web/src/features/operations/ProjectWorkbenchPage.tsx`及`project-plan-workbench-view.ts` | 当前状态、回应、判断、下一步与阻塞优先；旧事项放历史详情，完整目标与标准按需展开 |
| `apps/web/src/supervisor-workbench-stream.ts` | 订阅既有主管SSE元数据并触发只读刷新；不发送执行命令，登出或鉴权失效后关闭 |

主要入口如下，路径中的`:id`始终是实际项目ID，管理者本人身份与版本保护继续生效：

- `GET /api/v1/projects/:id/workbench`：返回既有context及新增`currentLoopBrief`，只读。
- `GET /api/v1/projects/:id/supervisor`与`/event-history`、`/events/:eventId`：核主管会话、历史和准确事件；不要用事项摘要代替这些来源。
- `GET /api/v1/projects/:id/supervisor/events`：既有SSE，`supervisor.changed`只含项目/修订元数据；页面收到变化后重新GET，不能凭事件推断执行成功。
- `POST /api/v1/projects/:id/supervisor/corrections`：按目标事件/H与CAS追加纠错；旧事实保留。
- `POST /api/v1/projects/:id/supervisor/commands`：明确的reply/start/pause/stop等动作。普通只读刷新不走此入口；原子kickoff和已有adopt/reconcile语义保持原保护。

管理界面自动回报中的`independentAcceptance`始终为false。若手工事项与新回包不同，先核当前run/结果H/目标修订和主管事件，不把旧摘要当当前事实，也不要直接重写数据库消除差异。

## 3 跨轮原件连续性与容量边界

### 3.1 来源链的信任边界

新判断从当前运行出发，只沿请求中已记录的前驱`consumedRunId/resultHash`追溯。每一源运行重核已接受的正常`signed-agent`终态、结果H、任务/项目/owner/scope/机器/执行器/工作区/原生会话和主管目标修订；既有原件验证器再次核完整receipt。公开`getRun`不返回owner_id时，使用执行运行时已有的owner过滤任务索引，不把字段缺省当外来owner，也不跳过owner核对。

旧目标或可信停止后的显式新原生会话是**排除边界**：验证边界来源后停止继承，不自动混入旧目标、旧native或无签名别名。`sourceRunId/sourceResultHash/sourceGoalRevision`等说明**哪个受控运行运输了这些字节**，不自动证明历史文档由该运行生成。旧f9用于定位报告和skip，不追加“f9必须是报告生成者”的新验收条件；不存在的旧`binding.json`或历史作者签名仍记unknown，不伪造。

同路径同H去重并保留全部`sourceBindings`；同路径异H明确冲突，不能静默覆盖。当前回包声明的原件缺失，即使历史运行有同路径同H，也仍标当前缺件，不能借旧件伪称本次完整。新增facts使用全新唯一路径，避免用相同路径更新内容造成合法但不可静默处理的冲突。

冻结审计有界：最多20源运行、120个唯一原件、262144解码字节；每次实际回包仍保原30件、单件32768B等采集门。无论哪一层超限，都明确阻断，不能截取原件后沿用原H。大dirty原文和二进制index本次保留与只读核查；没有声称已把全部原件无损运到模型，更没有把这一未实现传输能力新增为本组标准。

### 3.2 无损模型投影

完整`evidenceHistory`保存在私有冻结intent，模型侧只携其核验后的`evidenceAuditHash`。每件原件的完整`content/path/sha256/size/verified`和全部`sourceBindings`仍发送；仅省去与首个binding逐字段完全相同的五个顶层来源字段。来源表、manifest hash、原件内容H/size和映射不一致即拒绝，不能“尽量匹配”。投影再次执行或JSON往返后保持相同完整prompt，旧输入无此审计结构时保原行为。

完整正文、原标准、纠错、已选经验、来源关系和引用白名单均未截断；完整冻结输入仍用于执行前的陈旧/撤权检查。这个改动减少重复序列化，不提高采集上限或131072B完整prompt门，也不保证所有provider/token配置都能接受任意上限输入。

实际最后判断使用32件完整原件、71683解码字节、3个来源运行、4条纠错、60个经验排除metadata；完整contract加JSON为**125663B**，余5409B。此前实测新并集的未压缩输入140433B超限，修复后先做实际保存输入的离线计量，再进行真实判断，未用模型反复撞门。见[投影独审](../../artifacts/closed-loop-r53/evidence-projection-independent-source-review.json)、[真实保存输入计量](../../artifacts/closed-loop-r53/saved-real-union-prompt-budget-compacted.json)及[最后实际prompt计量](../../artifacts/closed-loop-r53/final-actual-prompt-measurement.json)。

执行指令内历史“JSON.stringify全部输入30000字节”说明是陈旧文本，不代表当前门又降为30000；本次没有额外源码修正它。维护者以当前共享常量、runtime/adapter/PiService实际调用链和绑定诊断为准。清理该说明应作为后续小变更留证，不因本文便追改旧运行文本。

## 4 纠错、显式接续与自然停派

1. 先核本文APP、当前prod版本、真实Git及是否有后来任务；本页不是日后继续复用的实时授权快照。保原日常开发目录，在112独立副本按规则开发，不并发改101同一需求。
