中央平台保存项目、任务、审批和运行回执。Pi 开发优先走原生 SDK；Claude Code、Codex 及固定发布程序通过独立节点 Agent 执行。仅配置模板不能证明执行成功：节点心跳、租约、真实进程日志和结果均单独保存，成功任务进入待验收，交付仍需人工验收。

本机 Pi SDK

在“运行配置”中配置执行器：engine: pi-sdk、machineId: local、执行器 ID（例如 pi）、独立项目工作区父目录、最大轮次、单轮超时、租约和 budgetCurrency: USD。中央平台复用 Pi 的原有认证目录。不要将模型密钥填入项目、执行器 argv 或 Agent 配置。

项目副本必须是工作区父目录内的真实子目录，并与任务机器一致。开发只使用开发、测试或预发布副本。Pi 工具限定在此目录中的读取、列表、写入和编辑；SDK 不能把聊天工具用作开发工具，不能触碰生产副本。设置实际 AI 预算后先手动执行一轮，再按需开启持续监督。

任务和项目所选 Skill 会在启动时按 experienceId/version 解析准确的已发布、已验证版本，旧版从历史正文中提取，不自动升级。正文、适用条件、验证证据及来源冻结到运行请求，单项与集合均保存 SHA256。最多 16 个不同版本，总原始文字 12000 字、序列化内容 16000 字符；超过上限明确拒绝。每轮 SDK 与 CLI 开发提示都包含这些固定资料，但资料不能改变权限、工作目录、执行器、预算或验收规则。资料越范围、缺失或停用会阻止启动/领取；运行中的节点在签名续租时也重新检查并停止失效引用。暂停、取消和历史回执保留原快照。

远程节点 Agent

  1. 在设备中心登记节点。公司机器可以授权遥测或显式经验采集，不能授权开发、休眠和发布。
  2. 在中央运行配置保存固定执行器模板，然后为此机器签发短期、一次性配对票据，明确执行器 ID、telemetry、capture 等能力。
  3. 复制 配置示例 到节点本地，填写中央 URL、机器 ID、票据和目录白名单。节点模板的程序、argv、目录必须与中央模板一致；LAN 地址使用 HTTPS，并将实际中央主机列入服务器的 JARVIS_ALLOWED_HOSTS。
  4. 使用 Node.js 24 和项目已安装的依赖启动：
node --import tsx apps/agent/src/index.ts --config D:\JarvisNode\agent.json

首次配对会在本机生成 Ed25519 密钥，移除已使用票据，并把配置权限限制给运行账户和 SYSTEM。中央仅保存公钥与票据哈希。进程要持续运行；注册台账或手工心跳不等同于在线节点。

Claude 模板使用固定可执行文件绝对路径和 --print --output-format stream-json --max-budget-usd {maxBudgetUSD}，预算参数须仅出现一次且紧邻分配额度占位符。Codex 使用固定本地入口、exec --json --sandbox workspace-write 或 read-only，--cd / -C 如有配置只能取 {workspace}。两类 AI 模板都必须配置 {prompt}，引用 Skill 的固定开发模板也必须接收此占位符。Windows 的 .cmd、.ps1 及 shell 入口不受支持；可固定调用 Node.js 加官方 CLI 的 JavaScript 入口路径。具体 argv 先核对本机安装版本的 --help。禁止注入 shell 代码、扩大目录或绕过权限。CLI 凭据留在该节点原生认证配置中。工作目录白名单限定平台派发目标；Claude 及固定程序的系统读写权限仍取决于运行账户和原生 CLI 的权限设置，不构成操作系统沙箱。部署前须在独立低权限节点账户中核对原有 CLI 权限。

节点校验中央租约、本地模板、真实项目目录和固定预算后才启动进程。输出脱敏，停止或超时会结束进程树；Agent 进程意外退出后子监督进程也会结束任务。节点须有 60 秒内的签名心跳才可领取；启用资源规则时，过期或缺失的 CPU、内存读数会阻止派发。CPU、内存、并发、安静时段和紧急停止在领取时检查。安静时段格式为 22:00-07:00，固定时区 Asia/Shanghai，跨午夜有效，结束时刻不包含。资源或预算暂不可用只延后新领取，不因额外领取失败杀死其他运行。

持续推进须管理员开启监督，且任务未到截止时间、预算和轮次未耗尽。原生 CLI 可明确配置 supervision：API 计费要求可核算费用；subscription 按真实 Token 和轮次限制续轮，未知金额仍保留未定价。Codex 未提供金额时，可配置匹配实际模型的输入/输出目录单价；否则 API 计费停止续轮。Claude 会话累计费用按匹配会话检查点取差额，缺少基线或费用回退时不推算。额度/网络失败可按策略有限重试，或切换本机同工作根目录备选；登录、权限和未知问题需人工处理。详见 双机接入。费用区分执行器报告、目录估算和人工供应商账单；未知费用不会代替成零元。SDK 失败或取消后的实际部分用量仍计入任务预算；旧运行迟到回执只追加费用，不会覆盖恢复后新运行的状态和租约。租约过期进入中断状态，需要人工决定恢复，避免自动重复执行。

主动与被动经验采集

先为具体机器、项目、范围和字段保存启用且同意的采集策略，再给节点授权 capture。节点每次提交都会检查最新策略，撤销授权立即阻止后续提交。原话进入收件，候选 skill 不会自动发布到经验库。公司只读机器须绑定明确的公司项目及 company 资料范围；无项目或跨范围不允许采集。

主动提交 JSON 文件的字段为 policyId、eventId、scope、可选 projectId、field、text、可选 title：

node --import tsx apps/agent/src/index.ts --config D:\JarvisNode\agent.json --capture-file D:\JarvisProjects\demo\capture.json

被动采集只读取显式指定的项目 JSONL 文件。Agent 配置 journals 的每项为：

{"path":"D:\\JarvisProjects\\demo\\lessons.jsonl","policyId":"固定策略ID","scope":"personal","projectId":"固定项目ID","offset":0}

每行仅允许 eventId、field、text、title，例如 {"eventId":"lesson-001","field":"lesson","text":"发布前先运行独立验证"}。采集保存字节游标并按事件去重。不扫描操作系统、私人文件夹或聊天软件；路径必须位于项目目录白名单。

发布、恢复与备份

服务健康探测只请求管理员固定配置的 URL，不接受任务提交的任意地址，不跟随重定向。WoL 仅发送已配置 MAC 的真实 UDP 唤醒包，收到新的可信心跳前保持未确认在线。休眠须对应节点具备固定 sleep:机器ID 执行器，并逐次明确确认。

部署先绑定服务、机器、项目、环境、固定发布版本、原版本和备份，再逐项审批。生产审批需逐字确认操作名称。deploy:服务ID 与 restore:服务ID 必须配置固定程序及独立验证程序，节点实际校验备份 SHA256，验证退出码及观察版本一致后才更新登记版本。恢复只能使用原批准备份与原版本；人工 external-pass 凭证不能进入真实恢复流程。

项目文件备份实际复制并校验每个文件。隔离演练复制到新目录，不覆盖当前项目或生产服务。平台活跃 SQLite 数据由平台一致性快照接口备份，不能当普通文件拷贝。审批预算与资源配置也保存固定数据库配置恢复点，回滚时检查目标未漂移。

执行 API 清单及请求/响应见 docs/openapi-v1-planned.json；运行日志支持分页和 SSE。execution.sqlite 保存节点、配置和租约，应与平台数据库及备份清单一起纳入平台快照。

R19 节点可靠回传

开发节点 CLI 在 agent.save(configPath) 后，默认使用私有配置同级的 .delivery-<agentId>/journal.sqlite；也可在私有节点配置显式指定绝对路径 deliveryDirectory。Linux 目录归运行账户、0700，数据库0600；Windows关闭继承并只授权当前账户与SYSTEM。父目录由安装方预建、不得含符号链接。101 的目录由部署工具单独建立，配对身份、密钥和执行器模板不变。

节点在执行前登记运行，脱敏日志和最终回执先进入SQLite待发送账本，每轮留下原生会话及累计计量检查点。待发送数据占用有边界，达到上限阻止新领取。私有账本包含租约、任务及检查点，不能作为公开报告上传；长期保留和清理需要单独策略。

签名日志/结果可带稳定 deliveryId，每次重送更新时间、随机数和签名；正文与递送身份保持相同。中央确认包含递送、运行、类别和正文SHA256。只有核对确认后才清理待发送内容；相同身份相同正文返回原确认，异正文拒绝。短暂错误有限退避，永久错误或到达尝试上限保持阻塞，不自动重新执行原任务。

日志以实际JSON UTF8正文分批，每批不超过96KiB，其他普通接口仍采用128KiB限制；签名最终结果单独限定2MiB，并在节点预检。默认待发送payload上限32MiB，预留2MiB+96KiB供终结及排空，条目上限20000。这些是待发送内容限制，不是SQLite、WAL、历史运行和检查点的全磁盘硬上限。达到边界时保留明确阻塞，不能把未发送结果丢弃后继续领取。

中央保存递送确认和原终端租约身份。晚到结果仍核对原节点、租约及运行范围，只追加允许的旧证据与实际消耗，不能复活已取消任务或覆盖新一轮租约。旧节点未带 deliveryId 的协议仍保留兼容路径，不能据此声称旧节点也具备本地可靠补传。

业务效果跨库通过先持久化的冻结意图与稳定业务命令身份恢复，重复回传不重复修订或加费用；真实计量保存原始汇总身份，与ledger同事务提交。observer后续补充只调整对应余量，不能改变原汇总重送身份。已经持久计量但随后到达预算线，停止下一任务而不拒绝已存在的消费证据。

stopReason 只含固定原因码及时间，局部详细错误先脱敏保存。节点重启将未结束运行记录为中止并补交检查点，不启动原CLI；中央需完成原进程、源码、费用及副作用对账后决定新运行。整轮检查点不是“原生会话崩溃自动续跑”已经通过的证明。

中央每运行仍采用原有5000条日志滚动保留；本轮可靠补传不等同于永久全历史日志档案。项目级自动拆任务、自动独立验收、可靠后备和连续24/72小时演练尚需建设，见 全天实施方案。

本轮的永久递送阻塞可在节点私有状态及服务日志看到固定原因码；尚无中央spool状态页或已验证的解除阻塞工作流。配对在线只表示节点连接，不能独自证明它仍在推进任务。
