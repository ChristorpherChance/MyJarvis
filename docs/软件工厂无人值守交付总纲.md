## 现行工厂能力与监管验收

### F01 · 工厂自身完整真实可用

安装部署后的工厂各适用功能与操作真实生效，状态、数据和执行结果可核对；页面能看、服务健康或局部通过不能替代完整可用。

### F02 · 客户原始资料开始

客户可直接提供原始资料；原件、目录和来源保留，长文、表格、图片、附件及扫描疑点有完整处理或明确缺项，重要歧义得到澄清，不要求先提供专业设计。

### F03 · 资料真正整理加工

资料的解析、整理、编辑、翻译、脱敏和批量处理按适用范围真实执行，原件与处理稿对应，失败、重试、定稿及下游引用可核验。

### F04 · 完整专业CRD PRD RTM HLD七LLD

形成内容完整、专业且相互一致的CRD、PRD、RTM、HLD及七册LLD；可编辑、确认、保存版本，空标题或只挂链接不算完成。

### F05 · 专业可复用模板

具备专业默认模板及项目模板整套保存与复用、同类模板选择和换源；用户模板优先，支持新增类别并经人工修改确认。

### F06 · 完整高保真与实际软件设计一致

所有适用页面、子页、角色、状态和终端有独立高保真及完整交互；实际软件逐项与批准需求和设计对照，关键流程、数据与权限行为真实一致。

### F07 · 真开发与自测/CI/审评合并

真实代码与仓库提交承接设计；开发自测、前后端联调、真实CI、独立审评及合并各有对应产物和结果，模拟结果与合成提交不算完成。

### F08 · 独立测试缺陷修复闭环

独立测试覆盖适用正常、边界和异常；问题形成真实修复安排、代码修复、新构建和回归结果。跳过、未运行、环境缺项和失败分开，不能只看断言通过数。

### F09 · 完整文档软件交付并目标实际使用

交付同版完整文档、源码及可运行软件包和说明，真实下载和完整性可核对；在已约定且获授权的目标环境安装，由目标角色完成真实业务使用。

### F10 · 升级恢复后续变更

验证安装升级、数据及配置恢复、回退、故障处理和后续需求变更；影响到的文档、设计、软件和验收同步更新，保留旧版本和原失败。

### F11 · Pi/AI/Agent子Agent真实能力

Pi/AI路由及各阶段Agent、子Agent真正执行职责，实际加载对应提示词、模板、工具和技能；委派、返回、取消、恢复、身份和用量可核对，登记名称不算能力。

### F12 · Agent持续改进且正常流程最终全自动

能力改进与全自动分别验收：真实问题形成改进候选，经独立对照评价、观察和必要回退；成熟后在完整输入和有效授权下，从原始资料到文档、软件交付使用的正常流程无需逐关人工点击。

## 7. 连续监督的正常循环与例外

每轮按**读取实际目标/候选 → 找就绪工作 → 派有界真实任务 → 收签名/真实产物及用量 → 独立核验 → 更新条款证据 → 有问题有限修复复验 → 自动安排下一步**运行。任务成功退出先进入待验；项目只有全部出口合格才完成。

| 情况 | 自动应对及停止边界 |
| --- | --- |
| 额度/限流/短时网络 | 按已验证余额、重置和路线有限等待/重试/切换，保持检查点和新尝试身份；未知成本不免费 |
| 无新产物/重复相同失败 | 定位工具、模型、环境、上下文或设计原因；实质修改后复验；到边界明确阻塞，不能无限“继续” |
| 进程/节点/服务中断 | 对账原执行、回执、用量和工具效果，安全物理续做；队列補传、重启和检查点不冒充全部恢复 |
| 父子部分失败 | 保留已合格产物，阻止缺项阶段通过，只补失败范围；暂停/取消和技术资源控制传播 |
| 上游变化/并发冲突 | 新输入/候选版本，定位受影响依赖并使旧证据失效；旧历史保留 |
| 外部接口/权限/目标缺失 | 按契约诊断、有限恢复或具体阻塞；不伪造成功、越权或假造客户环境 |
| 发布/迁移失败 | 停止扩大影响，按已配置恢复方案回滚并核对数据/文件/配置；未知副作用不盲重做 |
| 管理者主动暂停/取消 | 停活动执行及后续派发；晚到回调零写，不当异常自动复活 |
| 真正不能裁决的业务冲突 | 保存具体问题、已尝试/建议和影响，等待答复；已有规则可确定的正常项继续 |

项目级专项监督只派本工作流绑定的新任务；不复活历史已取消任务，不把全局开关关闭解释成不能专项执行，也不误开无关项目。阶段正常过关不再逐项问人；范围、权限和技术运行边界变化依据已有授权及有效配置处理。故障注入和试验在独立环境，不能为补证据破坏业务环境。

## 9. 真实性、从零验证与完成率

测试同时包括：软件工厂最新完整候选从清洁环境安装；客户新资料从起点经历所有阶段直到实际使用。旧服务冒烟或测试目录全跑完不替代全部当前条款验收。需求/设计/原型允许明确模拟演示数据；真实后端、模型、开发、测试和交付不许由模拟结果签收。

必须验证真实正例和拒收反例，包括错项目/错版本、模拟标记丢失、零用例/必测未跑、伪 CI、陈旧/重复/晚到回执、审计失败、取消复活及重复副作用。检查持久业务状态/决定，不只 HTTP 错误。至少代表性多页面项目应经历一次实际失败、实质修复、新构建/批次和独立复验。

条款分母来自当前完整冻结范围。本期必需条款 100%有承接与真实合格结果；历史RTM/UI比例和证据按原版本保留。关键项100%、单页一般项≥95%、严重偏差0不能掩盖必需页面或业务缺失。活动量、Token和执行器自报不是完成率。

先取得单阶段真实正反证据，再验证能力候选/回滚、代表性贯通、正常无逐关点击、异常/变更及多输入/环境的24/72小时稳定观察。次数、性能/费用/时间阈值按基线和配置实测，不预填绿色，不无必要反复重跑收费模型。

## 10. Agent 持续改进与技能复用

项目总控、阶段负责人及按需专业子 Agent 各有不可变定义；运行实例绑定实际输入/版本/模型、工具、父子任务、输出及用量。子 Agent 数量取决于专业/并发/独立复核收益，不无限递归。

改进闭环为：真实错误/低效 → 分类归因 → 有假设的隔离候选 → 独立版本评估集与未见集 → 同条件稳定版对照及跨阶段回归 → 匹配范围观察 → 达阈值自动提升 → 退化回滚 → 经验证经验技能。项目修好与能力优化各有结果，修改提示词不证明总体更好。

定义版本要真的注入执行器并在回执中核对正文/技能/路由/模板哈希；只存注册 ID 不合格。在途固定，提升/回滚影响后续任务。产出方不能自行降质量门、删失败、改答案或扩权限。质量与真实优先，保持同等质量后再比较速度/费用；小样本只声明本范围。

### 11.1 自主择优与决策台账

用户新增规则：AI遇到实际问题或可选方案时，在已授权项目范围内自主选择当前最合适的方案，并保存当时情境和回退依据。普通实现选项不再停下来等待人工选择。优先满足硬需求、真实质量证据、权限与安全边界，再比较可逆影响、兼容性、长期维护及实际速度/费用；费用只记录，不作为消费限额。

每个有意义的决定形成独立、可引用的记录，至少包含：

| 字段 | 记录要求 |
| --- | --- |
| 身份与时间 | 决定编号、项目/工作包/任务/尝试、发生时间和决策者 |
| 问题与情境 | 实际症状或需要选择的事项、当时可确认的事实与未知项 |
| 目标与约束 | 关联目标、当前质量/权限/兼容/运行环境和依赖条件 |
| 备选与利弊 | 当时真实可行的方案及主要利弊；没有实际选项不虚构，有方案不可用说明依据 |
| 选择与依据 | 所选方案和简短、可复核的理由；保存结论依据，不输出完整思考过程 |
| 版本与证据 | 输入、源码、设计/Agent/模型/配置版本及当时证据指纹 |
| 影响对象 | 受影响项目、机器、服务、工件、用户角色、数据及后续依赖 |

状态分别记录 `selected`（已选定）、`implemented`（已有真实实施证据）、`accepted`（独立验收通过）。选定方案不能增加产品完成率；实施后仍可能未通过。情境、版本或证据变化时，追加新决定并引用被替代的旧编号，保留原理由、影响与回退记录。失败、撤回和反例同样保留，不覆盖历史。

源码工作任务将公开、脱敏的决定追加到工作副本 `docs/jarvis-decisions.md`；平台决策台账与建设记录分别承接真实记录及其版本。普通实现选择自动处理；业务需求真正冲突、缺少无法推导的客户输入、越出授权或存在未解决副作用时，记录具体例外和恢复条件，不能靠自选方案取消验收要求。私密资料、凭据和完整思考过程不进入文档或公开台账。

此规则适用于后续项目的监督复用，是本轮新增运行规范；74个已冻结目标及其验收条款保持不变。运行规则的实现、上线及验证在第14节单独记录。
