1. 推荐落地方式

采用 32GB 开发环境＋48GB 生产核心＋独立算力服务＋i3 房间终端。这一分工将开发、正式运行、模型计算和房间交互分开，适合作为首期部署方案。48GB 机与 QNAP 常驻，实时语音至少有一条常驻且经过验证的算力路线；重构建、OCR 和批处理按任务运行。

32GB 的 i5-7400 是平台主开发环境，HP 和联想仍可用于编辑、远程开发及维护。32GB 内存适合首期轻量开发环境，但 4C4T CPU 需要限制同时构建、测试与后台工人的数量；重计算调用独立接口。48GB 机承载业务与数据，后台开发执行器安排到独立工人，保护家人正在使用的生产服务。两台机器的 256GB 磁盘余量和健康度优先核验。

延续 V5 的“模块化核心＋独立任务工人”：九个业务域明确数据归属，首期共用业务应用和数据库；语音、OCR、索引、研发执行等工人独立运行。逐步交付可以使用的功能，业务量增长后再拆分服务。

正式平台通过网址访问。电脑管理、手机管理、各领域大屏和语音终端调用同一套后台接口。V15 保留为设计基线；生产前端将拆成组件、按需加载主题资源，并处理网络异常、身份权限和真实状态。

图中为逻辑部署关系。生产应用与数据库集中在 48GB 机，首版依靠备份和人工恢复保障可恢复性；这是单机生产，自动故障接管需要后续单独建设和验证。

4. 平台每天如何运行

4.1 设备、项目和大屏

设备上报心跳、资源、项目关联、服务状态和时间。建议心跳起步约 60 秒，连续三次缺失标记连接过期，后续按网络实测调整。任务变更即时推送，界面显示来源、更新时间与最后已知状态。

管理员在任意已接入电脑上登记项目与工作副本。后台任务在独立分支和工作区运行，一个写入工作区只归一个执行者。本人临时维护某服务时可以暂停自动操作；恢复权限后再续接。

Core 聚合这些事件，供总览、大屏、手机和语音查询。模型负责解释事实或形成建议，任务进度由阶段和验收证据汇总，未知状态明确显示。公司 HP 首期按指定范围只读接入，敏感资料由本人选择分享。

4.2 全天开发监督

本人设置目标、验收、允许的工具与目录、预算、运行时段和停止条件。48GB 生产机负责监督、派发和记录；独立 i3 / E5 工人领取任务，在本机启动执行器，将事件、提交、构建与测试产物上报。平台自身开发可在 32GB 开发环境执行；需要关机后继续时，先托管到有完整环境的工人。

监督过程为：派发 → 执行 → 独立验证 → 未达标时有限续作 → 达标后形成交付包。正式部署另有授权与健康检查。进程退出、一轮回复结束、验收通过、部署成功和线上健康分别记录。

首版为 Codex 与 Claude Code 分别实现适配器。可使用 Codex 非交互结构化输出，以及 Claude Code 程序化调用、流式事件和会话恢复；平台以自己的 Agent 通道跨机器传递任务。Codex 非交互模式、Codex SDK、Claude Code 程序化运行。

已有桌面会话先接入观察；要托管续作，需确认执行器可用的接口、工作区和授权。后续可评估节点本地的 Codex App Server stdio 接入；其 WebSocket 传输目前属于实验用途，不作为首版生产跨机器底座。Codex App Server。

Core 全天监控，执行节点在任务期间保持开机。HP 关机后，已经托管到后台节点的任务仍可继续；只在 HP 上运行的任务进入离线或等待状态。迁移任务须带上仓库、环境和检查点并确认旧执行者停止，不能只搬一个会话 ID。

任务与每次执行尝试持久保存，使用唯一标识、租约、心跳和去重。断网恢复先核对原进程，避免重复启动并同时改同一目录。人工暂停、权限拒绝、缺少输入、预算/额度耗尽、重复失败达到上限时进入对应等待或阻塞状态。提前批准范围内可持续推进，范围外动作形成具体审批项。

模型预算按渠道分别设限与记账。Codex 使用 ChatGPT 登录时受订阅权益与额度约束；使用 API key 时按 OpenAI Platform API 用量计费。额度耗尽后不自动切换付费渠道。Codex 官方认证说明。

4.3 家庭语音和个人记忆

首版采用 i3 本地唤醒／拾音 → 生产核心协调识别 → 身份与意图确认 → 查询／任务与对话生成 → 合成 → 原房间播放，支持流式播放、打断和任务回执。ASR、TTS、OCR、向量生成与文本解读由算力接口提供，身份、记忆、权限、业务事实和任务状态由生产核心保存。

房间实施次序为：一楼客厅 → 二楼书房 → 厨房／餐厅候选。卧室暂不部署。i3 主要负责交互、短音频缓存和离线提示；每个房间不另建长期记忆库。终端能力可先评估具备本地关键词检测与 VAD 的方案，实际唤醒词、语言、误触发和延迟须现场验证。sherpa-onnx 官方项目。

固定终端负责拾音、唤醒、回声处理和播放。通常保持本地唤醒，只把触发后的必要音频送入识别链路；提供物理或清楚可见的静音入口。普通浏览器需要麦克风授权和安全来源，全天唤醒优先使用有后台音频能力的专用终端组件。MDN 麦克风接口说明。

每个人独立配置声音、唤醒词、交流方式与记忆范围。声音和声纹帮助选择档案；敏感记忆与管理动作需要可靠认证。身份不明确时使用家庭公共范围，随后确认个人档案。原始音频默认不长期保存，会话与长期记忆按本人保留策略处理；候选偏好确认后才能成为正式记忆。

房间身份、终端身份、会话身份和成员身份分别记录，避免把“厨房正在说话”直接认作某位家人。跨房间继续对话需确认原会话与播放交接；同一句唤醒被多个终端听到时由协调器选择一个响应端。两处可同时对话的能力单独实测，不以终端数量推定模型并发。

若 4070 改为专用 AI 服务机，可作为实时算力常驻节点，32GB 桌机承担平台开发；若仍兼任家用，则需要经过验证的常驻 CPU、备用 GPU 或本人允许的云端语音路线。隐私模式只使用本地能力，能力不足时提示降级，不能悄悄转云端。实时 ASR / TTS 与大型 OCR、书籍解读采用不同任务队列和资源限额，确保批处理可暂停或让出资源。

客厅与厨房的电视、抽油烟机、餐具声，以及终端自身播放都会影响交互。优先验证麦克风、扬声器、摆位、回声消除、噪声处理和插话；厨房小机应远离油烟与水汽，可将音频外设和主机分开放置。屏幕可选，全天唤醒使用具备后台音频能力的终端组件。

4.4 知识神殿与经验成长

书籍扫描原件写入 NAS，保存哈希、页序和版本；工人从本地缓存解析。OCR 输出进入校对暂存区，疑点、人工决定和原文修订入正式数据。只有达到约定质量门槛并发布的版本，才能生成正式教学故事与索引。

知识关系、故事和课程均链接具体原文版本与页段。校勘变更触发派生内容复核与重建。反复 AI 一致不能证明零错误；无新证据的复核设上限，未决关键疑点交人工并阻止相关内容发布。先用约 30 页含古文、异体字或复杂排版的样本校验，再处理整本书。

外部知识源通过连接器动态注册，可添加、停用、增量同步和撤权。连接数量可扩展，实际容量、费用、授权和处理速度分别限额；撤权时取消检索资格并清理适用的索引与缓存。

任意终端提交的灵感与经验先进入收件区，关联机器和项目，再整理、去重、验证。经过验证的 Skill 发布为版本化文件，按适用环境提供给后续执行器；使用结果回流。知识缺口、证据冲突、学习薄弱点和重复问题均可形成有出处的建议，由本人或家人决定采用。

5. 服务发布、恢复与资源保障

5.1 开发、预发布、正式运行

32GB 桌机保存平台开发环境；HP、联想或其他电脑可远程开发与维护。开发、测试和预发布使用独立配置与数据库，首期在开发机上按需运行；复杂验证可交闲置 i3 或 E5。每个交付包包含源码版本、构建产物、配置模板、数据库迁移、验证报告、部署与回退说明。验证健康和恢复后，再按有效授权部署到 48GB 生产机。

正式服务交给容器或系统服务管理，并配置启动、健康检查、日志限额和失败告警。已经运行的自研项目先登记所在机器、版本、启动方式、API 和恢复方法，只读监测；后续逐个纳入发布流程。

回退前检查数据库变更是否兼容。破坏性迁移要有可验证的恢复路径，前端版本回退不能代替数据恢复。首期不承诺升级无感或自动切换。

5.2 数据与备份

活跃数据库、开发目录、解析临时文件和热索引放本地 SSD。NAS 保存大文件、原件、正式产出和备份。256GB 小盘要设置缓存清理与最低余量，扫描量和工作区增长到阈值时再规划扩盘。

先建立每日数据库一致性备份、定期文件增量备份和 NAS 之外的关键加密副本。备份内容涵盖账号、任务、记忆、知识源配置、原文版本、Git、必要密钥恢复材料及删除标记。恢复到冷备环境后验证真实业务，记录耗时与可恢复时间点，再确定恢复目标。

忘记个人记忆时撤回记录、摘要、索引与缓存；恢复旧备份后重新应用删除标记。保留期内的备份按策略到期清理。NAS RAID 和快照可辅助恢复，仍需独立副本。

5.3 故障与降级

情况 应有行为
家庭断网或云模型失败 本地采集和可用的本地查询继续；需要云端的任务等待，语音按已批准路线降级
数据库失败 暂停需要持久确认的新业务动作；端侧暂存有唯一标识的事件，界面显示过期状态，恢复后去重补传
NAS 不可用 暂停依赖原件或归档的新任务；有缓存的读取按权限继续，缓存不可当作已完成归档
开发节点失联 标记执行尝试失联，先核对旧进程与工作区；确认停止后才恢复或迁移
48GB 生产机故障或断电 本地房间唤醒可继续，中央记忆与业务服务不可用时给出明确离线提示；恢复生产机或在冷备上恢复最低业务能力，UPS 和来电恢复顺序经过演练

在预留给自动任务的资源配额内，调度优先保障家庭实时语音，再处理必要查询和后台开发，OCR 与资料批处理排队；本人正在使用的开发资源不被强制抢占。CPU、内存、GPU 显存、并发、模型费用和日志保留设独立限额。功耗、语音延迟和并发能力以实测为准；UPS 容量依据真实负载与目标续航选择。

私网设备访问按用户、节点标签和端口显式限制；再由应用身份控制数据范围。Caddy 可提供 HTTPS，使用内部证书时还需让客户端信任相应证书。Tailscale 访问策略、Caddy HTTPS。

6. 分阶段实施与验收

阶段按结果放行。工期在基础环境盘点及第一条真实链路试做后估算；持续开发和家庭语音可在底座完成后并行推进。

阶段 建设内容 放行条件
0：实机核验 核验 32GB 开发机、48GB 生产机、算力节点与冷备；确认房间音频与网络 清单对应实机；备份和迁移范围明确；生产与至少一条常驻语音路线稳定性测试通过
1：平台底座 登录与权限、Core、数据库、基础 Agent、真实总览、项目登记、经验收件、备份恢复 至少两机器、一项目、一既有服务真实上报；两人数据隔离；重启与恢复后记录正确
2：首版可用 独立工人的 CC/Codex 开发闭环；客厅语音通过后扩到书房，厨房餐厅现场评估 开发派发→验证→交付；固定终端唤醒、打断、个人档案、重复唤醒协调有效；人工暂停与离线不误续作
3：双神殿 样本 OCR、疑点审核、原文发布、故事引用、知识源接入与遗忘 样本逐页可追溯；未决疑点阻止发布；两人学习进度独立；撤权与删除后不再召回
4：完整交付 灵感→研究→项目；经验→Skill→复用；预发布→授权发布→健康检查与恢复 一小项目完成全过程，部署与验收有证据，一次恢复成功，经验可在下一任务复用
5：扩展优化 增加机器、知识源、房间和项目并发；资源调度、专用语音节点、必要服务拆分 容量、成本、延迟、夜间持续运行和故障演练结果支持扩容；新增组件有恢复方法

首个可用版本应至少支持：查询真实机器与项目；语音询问进度；托管一个明确的小项目；从开发终端提交经验；两位家人的记忆隔离；管理大屏显示事实状态。随后将知识生产、课程、深研与运维交付接入。

阶段 2 至少模拟一次断网、重复事件、执行器退出、审批拒绝、预算/额度不足与人工暂停。阶段 3 验证勘误传播和恢复备份后的遗忘状态。达到这些条件后，再把任务数量和知识规模扩大。
