# 项目验收与缺陷中心 · 本地首版

## 入口与职责

在真实平台的项目详情展开“项目资料与开发副本”，选择“验收缺陷”或“交付版本”。链接使用 `projects/<项目ID>?tab=acceptance`、`?tab=releases`。本地首版尚未部署；生产当前页面不因源码完成自动更新。

验收概览读取本项目已有任务的人工验收声明和本地缺陷分类。尚无完整需求/用例映射时明确待建立，不从缺陷为零、模型达标或任务数量推算项目通过率。

## 缺陷闭环

1. **新增缺陷**：填写标题、P0—P3严重度、复现步骤、预期/实际、标准、环境和发现版本。任务、运行、交付版本关联可不填；填写则服务器检查本人、项目和范围。
2. **开始修复记录**：可关联已存在的同项目修复任务。这里只记录，不派发任务。
3. **提交修复候选**：明确源码commit、构建SHA-256或已有交付版本至少一项，附修复摘要与证据引用。每次提交生成新的修复代次。
4. **记录人工复验**：绑定当前修复ID及候选指纹，填写通过/失败/受阻、范围、证据和理由。未通过/受阻回处理中；通过后仍未关闭。
5. **显式关闭**：只接受当前修复代次的最新通过复验。关闭不改任务、里程碑、监管或项目完成状态。
6. **重新打开**：保留旧关闭与失败历史，废止旧复验资格；重新提交新修复并复验。

修改验证对象或发现版本会清除当前关闭资格；旧候选、旧复验或其他缺陷的命令不能关闭新记录。所有写入有版本检查和命令幂等，冲突保留草稿，不自动覆盖新版本。

## 证据与权限边界

- 证据输入“安全相对路径 SHA-256”，只是本人声明与引用。服务器不从用户给的路径读任意文件，不把填入摘要称为原件已验证。
- 历史逐版追加并保留hash链，拒绝改删旧修订。任务、执行结果和release仍由原模块管理。
- 归档项目只读；本人管理员读取及写入均重新检查当前身份。公司范围的本人项目可记录质量事实，但不因此获得新的机器执行权限。
- 数据在既有jarvis.db专表，不增加独立库；写事务不嵌套调用另一连接的V1写入。备份恢复按现行整树发布恢复执行，不把旧backup脚本当完整平台能力。
- 软件工厂报告的缺陷仍是只读外部来源，没有变为本地可编辑的同一权威。

## 交付版本首版

只读显示既有不可覆盖release：版本、来源任务、固定验收和产物字符串。项目限定分页先筛归属后分页，不会只读全站第一页漏掉目标项目版本。

**这不是实际生成ZIP、下载、安装或部署。** 当前首版不新增发布按钮。后续登记版本继续复用任务的人工验收与package合同，实际软件包、部署健康和用户签收分别留证。
