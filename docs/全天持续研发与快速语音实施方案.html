贾维斯的目标是全天保持监管，在已确定的范围内自动开发、测试和修复；遇到额度等待时保留工作，恢复后继续。关键是持久的任务状态、客观验收、可靠恢复和正确的下一步安排。只让某个模型反复运行，无法保证最终交付。

本文把推荐方案与本轮实际实现分开。首项目仍以软件工厂现有 PRD 为范围，生产自动发布不在其中；全局持续监督是否开启，以正式平台配置为准。

1. 全天运行怎样组织

角色 部署与职责 依据
调度与监督 112 保存任务、依赖、预算、运行与恢复链；定期挑选就绪任务 持久状态及明确任务，浏览器关闭不影响监督
开发执行 101 在任务独立副本内运行 Claude；后续可增加 Codex 节点 执行器真实路线、目录、权限和运行身份
独立测试 对明确候选构建运行固定测试及反例，保留失败 真实文件、源码/构建指纹、实际进程和报告
诊断与修复 按失败分类生成有限修复任务，修完再跑受影响测试 真实错误及实质差异，同一错误无变化不反复重跑
验收与归档 汇总条款—产物—测试证据；形成交付候选和未完成项 模拟、未执行、未知或过期结果不得算通过

112 是监督中心；101 开发节点重启后先补传旧记录并核对旧运行，再领新任务。NAS 可作为证据与备份目标，需先落实实际保留和恢复策略，不能把“NAS 已接入”当作备份已完成。

2. 一条任务的完整循环

目标与验收 → 就绪检查 → 独立副本执行 → 固定测试 → 失败分类 → 有限修复 → 新候选复验 → 汇总交付依据。

步骤 自动做什么 什么时候退出
就绪检查 核对源码、依赖、模型、授权、价格/计费方式、剩余预算及资源 依赖未满足、来源冲突或预算不可判断时等待
开发 续接明确任务的会话及检查点；留下真实改动 达到目标、超时、无有效进展、费用/轮次到限
测试 运行固定工具，绑定当前输入与构建 所有必需检查有真实结果；缺报告保持未完成
修复 根据失败形成明确修复包，保留旧失败 同类失败达到恢复上限，或需要更改目标/权限
复验 根据改动跑必要回归，阶段完成再跑完整范围 新候选有合格证据；原失败不能删除后当通过
下一任务 按当前依赖和验收出口选择已授权的后续工作 范围完成、预算到限或没有可执行任务

常规开发、测试和修复可以自动推进。任务定义或范围需要实质改变、提高预算、追加权限、产生不可逆副作用时，应给管理者具体选项。软件工厂 PRD 已约定的人工定稿/交付点保留对应策略；不能借无人值守绕过产品门禁。新的自动验收策略需要清楚区分“内部工作单元验证通过”和“产品正式交付”。

3. 如何决定下一步，避免空转

监督器先用可核对的状态与规则决定是否重试、等待、测试或停止；强模型用于需要推理的诊断、计划和评审。调用模型前先做确定性的规则检查，减少无必要的费用和等待。

每个项目需要一份执行约定：目标与明确分期、验收条款、任务依赖、允许写入的副本、模型路线、预算、工作时段、恢复上限和停止条件。预算必须在平台形成实际配置，本文不擅自填写全天费用额度。

进度以已验证条款为分母；Token、运行时长、日志条数或模型自述只说明活动，不说明完成率。没有新产物或同一失败反复出现时，监督器应记录停滞及原因，改变输入或修复后才继续。

完成一个任务后自动安排后续就绪任务，需要额外的项目级编排机制。当前单任务 CLI 多轮续做和 dependsOn 不能直接证明已有任意依赖图、自动拆任务、自动验收或全天交付能力。

4. 异常处理与恢复规则

异常 推荐动作 恢复条件
短暂断网、可识别 5xx 有限退避，保留待发送记录 连接恢复，先确认原操作是否已提交
模型额度或限流 按实际回执等待；有合格后备时评估切换 额度恢复或后备已认证、计价且任务兼容
登录失效、权限不足 保留工作，显示明确待处理项 认证或权限问题已解决并验证
原生会话中断、上下文满 核对检查点和源码，组装续做包 明确 session 或新会话输入、费用增量及剩余预算
节点重启、旧运行失联 先收尾、补传、对账，不直接重跑 旧进程终结或隔离，副作用和产物状态清楚
日志或回执响应丢失 稳定递送编号重送，服务器返回原确认 同身份同正文去重；不同正文拒绝
验证失败 实际错误交给修复执行器，强模型处理疑难原因 新候选与实质修改，受影响检查通过
未知费用、结果或副作用 记录未知并暂停自动扩展 完成对账，不能把未知写成零或失败后直接重做
磁盘满、OOM、资源紧张 停止新派发，保留最后有效状态 资源恢复且状态核对完成
人工暂停、取消 保留决定；暂停等待继续，取消结束当前安排 不通过节点重启或补传自动复活任务

恢复统一经过：停止原因 → 原进程状态 → 回执/费用/产物对账 → 当前目标和预算 → 新运行续做 → 独立验证。服务自动重启只恢复服务在线，不能等同于原任务安全续做。

模型切换不等于换一个名称。需核对认证、真实回执、工具能力、价格、目录与会话兼容性。跨提供方往往需要新的会话和经核对的任务续做包；原生 session 不能假定通用。

5. 101 的模型分工

本轮用户指定最高能力路线为 gpt-6.1-sol[1m]。这里按网关与原生 CLI 的实际标识配置，不根据名称声称官方能力排名或上下文窗口已经实测。

工作 推荐路线 选择原则
项目整体计划、复杂架构、疑难诊断、重要评审 gpt-6.1-sol[1m] 明确强模型，实际回执必须可核对
常规实现、修改、小范围修复 首批使用已核实的强模型执行器；随后按真实质量与耗时评估标准路线 不为了分级提前引入未验证的后备
汇总、格式整理、简单分类 有效的快速模型或本地规则 不能负责最终质量门禁
编译、测试、扫描、状态查询 固定工具与本地规则 不额外让模型“模拟执行”

有三层独立路线：112 贾维斯 Pi、101 外层 Claude/cc-switch、软件工厂内部 Pi。101 模板指定 --model 约束外层调用；不会自动改变另外两层。工厂内部登记路线不等于进程实际生效，必须查询有效运行提供方。

本轮前的实际快照：101 外层默认 gpt-6-sol[1M]，强档别名也指向旧 sol；专用模板没有显式模型。现在已完成下列调整，并保留之前的报告。

层级 本轮核实的实际安排 状态
101 贾维斯开发执行器 Claude 固定参数 --model gpt-6.1-sol[1m]；最高路线经 gw.superopen.top 中央与节点模板一致；真实原生回执精确匹配
101 原生 Claude / cc-switch 默认、Opus、Fable 均为 gpt-6.1-sol[1m]；Sonnet 为 gpt-6-luna[1M]，Haiku 为 gpt-6-luna 只改当前 Claude 配置的模型字段；认证及其他 provider 保留
101 软件工厂内部 Pi 规划、生成、评审、聊天登记 gpt-6.1-sol；解析、翻译登记 gpt-6-luna 登记值，实际内部 provider 未证实；没有声称已接通或改成 [1m]
112 家庭对话 快速：cc-gateway 的 Kimi-Coding/kimi-for-coding-highspeed；高级：superopen 的 CPA / gpt-6.1-sol 沿用当前路由，不由开发执行器参数覆盖

最高路线真实探针使用一个受限、无工具、单轮任务，2,322 Token，独立验证退出码 0；目录估算 0.01217 USD，不是供应商账单。此探针证明指定模型接通及签名计量，不能证明软件工厂产品通过或一百万上下文容量已经实测。cc-switch 代理与自动切换仍关闭，后备执行器为空；后备必须单独验证，不能根据已填密钥直接宣称可切换。详见 模型路线核验。

6. 回答既准确又快速

把语音总等待拆成：结束说话判定 → 识别/语言判断 → 路由/上下文 → 模型首字 → 首句可播音 → TTS → 下载/播放开始。必须分别记录真实时间，过渡语不能冒充正式答案已经变快。

环节 推荐做法 准确性边界
自动输入语言 ASR 自动识别，保持中文及英法德输入能力；固定输出语言另管 不能拿父母的中文输出偏好强制中文输入
普通聊天 快速路线、精简当前有关上下文，完整短句先播 不截断原意，不读思考或结构化草稿
复杂问题 强模型给核对后的简短结论，再展开 没有证据时只给中性等待提示，不能先猜事实
新闻与实时信息 有真实查询结果后回答，保留来源 旧缓存或模型记忆不能当今日事实
TTS 首句优先、后句预制与播放并行，持续核对播放回执 不打乱句序、不遗漏尾句；打断后取消后续声音
等待提示 短、自然、遵守成员输出语言；最终答案到达时及时让位 不制造“已查询”“已执行”等虚假进度
声线 保留用户选择，展示该引擎实测耗时 不能把喜欢的慢声线悄悄替换成另一人声

本轮基线发现：中文合成夹具自动识别约 2.68 秒，英文约 4.92 秒；模型首字约 1.23–1.53 秒。英文普通科普未进入原先较窄的提前播音范围，仍等待整轮完成。客户端轮询及后句预制也存在串行等待。基线使用真实模型与服务器引擎，但没有完整运行手机播放链，不能当作手机端总耗时。基线记录。

保持同一 Whisper 权重、int8、beam=5、自动输入语种及其他解码参数，将 112 识别线程从 2 调为 4，英、法两段合成夹具分别从 5.00→3.14 秒、4.87→3.04 秒，识别文字、语言与概率相同。正式 worker 已调为 4 线程，保留原参数和成员偏好；这两段夹具不能代替所有语言、真人口音及噪声下的准确率验收。线程对照 · 正式配置验证。

语音候选还扩大了中英法德稳定学科常识的首句播音范围，保留实时查询、私有数据、执行动作与医疗等门禁；短首句优先，后句预制与当前播放重叠，等待期间更及时读取准备结果。保持自动输入语言、家庭固定输出语言、选择声线、打断、计量和不读思考内容。模型服务自身波动、上下文长度和真人收音仍需分别解决，不能把一句过渡语当作答案变快。

历史短句 TTS 报告中 Matcha 约 0.1 秒，Kokoro 约 2.8–4.4 秒，属于当时合成夹具；今天默认中文引擎是 Matcha，英语实际走 Piper。用户实际体验需按声线、网络、输入语言、上下文和播放环节一起核对。

浏览器可按网络数据块持续读取并消费，无需等响应全文；这支持首句串流的实现方式，但不能由浏览器 API 本身推断实际手机首声耗时。MDN 流式响应说明。ASR 的速度和准确度受模型、硬件与解码配置影响，参数改变需同夹具复核，不直接用项目基准代替本机体验。faster-whisper 项目说明。

7. 分阶段达到全天无人值守

阶段 建设内容 出口证据
A：可靠递送 原子落盘、日志/最终回执待发送、中央持久确认、停止原因 断网、响应丢失、重启、重复正文与伪造正文反例
B：原生恢复 每轮检查点、session/代码/费用对账、可靠后备与资源收尾 实际 Claude 中断、额度等待、后备切换、旧进程确认
C：质量闭环 真实性门禁、固定独立测试、失败→修复→新候选回归 模拟/零用例/陈旧证据拒绝；真实合格正例通过
D：项目编排 按验收条款拆工作、就绪调度、停滞检测、预算与依赖 一个完整小项目自动走完开发、测试和修复
E：持续运行 定期健康检查、备份、故障演练、资源保留、运维提示 先短时演练，再连续 24/72 小时观察，保留实际故障及恢复

首个软件工厂项目建议先稳定固定源码副本和 A/B/C；项目本身的范围、真假执行和交付门禁未清楚前，不扩大成无限开发。当前完整测试报告仍是 NO-GO，新源码尚未验收。

8. 本轮实施结果与入口

正式版本：20261010-autonomous-voice-r19-1。 112 主平台与 101 冷备已发布同版，101 已配对开发节点升级了可靠递送包，身份、凭据与强模型模板语义保持一致。全局持续监督仍关闭，软件工厂仍为 NO-GO；本轮没有派发新的源码开发任务或更改产品验收。
