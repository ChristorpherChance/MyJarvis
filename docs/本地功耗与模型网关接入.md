## 怎样计算，哪些数字不能混用

CPU 功率 = RAPL 能量计数器增量 / 实际采样时长，正常窗口约 2 秒；计数器绕回按最大能量范围处理。只取 package 域，不能再叠加 core、uncore 或 psys，否则边界不同或重复计算。RAPL 不是插座电表。[Linux 内核说明](https://cdn.kernel.org/doc/html/latest/power/powercap/powercap.html)

整机范围使用 CPU 芯片读数，加上内存、SSD/HDD、主板与风扇的粗估，再考虑电源损耗。工程假设：主板/风扇 8–18 W、每条 DDR4 1.5–3.5 W、每个 SSD 0.5–4 W、每个 HDD 3–8 W、电源效率 72%–90%；CPU 读数用 0.8–1.2 系数扩宽范围。这些是**未校准假设**，不是 HP 官方功耗或精确误差区间。

缺少芯片读数时，仅依据真实 CPU 使用率和硬件清单生成更粗的范围。三个处理器标称 TDP 均为 65 W，但 TDP 不是实时功耗，也不是整机插座功耗。[i7-7700 / i5-7400](https://www.intel.com/content/www/us/en/products/compare.html?productIds=97128%2C97147)、[i5-6400](https://www.intel.com/content/www/us/en/products/sku/88185/intel-core-i56400-processor-6m-cache-up-to-3-30-ghz/specifications.html)

估算不包括显示器、交换机和外接设备；离线、签名采样过期、CPU 型号变化时不会按零计算或继续给出旧值。月度电量当前是场景推演，没有声称已完成实际累计电量统计。

建议每台主机接带电量统计的插座电表，采集空闲、正常运行和高负载时的读数；届时可校准范围，并按真实累计 kWh 计算电费。现有“运维费用 → 实测功耗”可保存单次仪表读数及依据。自动电表适配和校准算法尚未实现。

## 采集与接口

本地三台安装独立只读采样定时器，固定读取内核能量文件并写入公开的功率摘要。监管账号读取摘要后签名上报，无需增加监管账号 sudo 权限；内核计数器原有权限保持不变，也不修改 CPU 功率限制。云服务器没有安装此采样器。

| 接口 | 用途 |
| --- | --- |
| GET /api/runtime/power | 当前本地估算、CPU芯片读数、排除项和总量 |
| GET /api/runtime/power/profiles | 经核实的本地硬件清单 |
| PUT /api/runtime/power/profiles | 按版本更新硬件清单，只允许本地个人设备且CPU型号一致 |
| POST /api/settings/pi/gateway/discover | 私有认证读取网关模型列表 |
| POST /api/settings/pi/test | 发送最小真实测试消息，记录实际模型用量 |

原签名心跳新增可选 cpuPower，严格检查来源、采样时间和功率范围。整机估算保留在独立返回字段，不混入实测 powerWatts 历史。Pi 新增管理员只读功耗查询工具，可回答本地服务器功耗问题。

## 模型网关

已验证 [SuperOpen 网关](https://gw.superopen.top) 可访问。根接口公开标明 next-ai-gateway / claude-code-router，提供 /v1/messages 与 /v1/models；未经认证读取模型列表返回 401，因此采用 **Pi 原生 Anthropic Messages 兼容接口**，基础地址使用网关根地址，由 SDK 拼接 /v1/messages。

“系统设置 → 模型接口”选择 SuperOpen 网关，填写密钥，读取可用模型，选择模型并保存。模型编号以网关实际目录为准。点击“验证真实对话”会发送一条简短检查消息，记录 tokens。保存成功只表示配置和凭据已经保存，必须通过真实对话才能确认模型可用。

凭据通过 Pi 原生登录接口保存在服务器私有 auth.json；模型目录不包含密钥。页面不会回显密钥，也不写入浏览器存储。留空保留已保存认证。新网关目录默认只启用文本、保守上下文 32768 / 输出上限 4096；图像、推理和更大上下文需按实际能力再开放。

已完成真实接入：网关返回 9 个模型，默认使用 **CPA / gpt-6.1-sol**，Pi 原生流式对话已返回“连接成功。”。这是网关登记的模型标识，不额外声称已核验底层厂商身份。凭据位于 112 的 Pi 私有目录，服务重启后仍能使用；本机临时密钥文件已删除。

已适配网关目录与实际调用编号的差异：目录中的 CPA / CLIProxyAPI/gpt-6.1-sol 实际应以 CPA / gpt-6.1-sol 调用。只移除这个经验证的展示命名空间，保留 CPA 目标；其他模型编号保持原样。

已完成浏览器真实验收：管理员对话成功调用 jarvis_power，只读查询三台主机的估算功耗；流式回答完成且会话落库。验收会话为“模型接入验收 · 功耗查询”。 模型配置修改后，需先保存，再验证当前模型，避免验证旧配置。

101 本次同步的是代码，仍保持冷备；112 的最新凭据与数据尚未持续复制到 101。正式接管时须按恢复方案同步最新私有数据。
