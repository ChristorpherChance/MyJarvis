# 发布时保留旧页面使用的静态资源

本规则修复跨独立工作副本升级时旧哈希JS/CSS丢失的问题。`promote-web.mjs`仍只负责同一个构建目录的合并，不能代替正式发布的资源传承。它不证明某次访问故障只有这一原因。

## 打包合同

`scripts/package-capture-release.mjs`现在必须显式指定至少一个已验上一包，每项同时带完整ZIP SHA-256。没有默认“首次发布”豁免；缺输入在读取源码和生成包前拒绝。

```text
--previous-package=<64位SHA256>:<ZIP路径>
```

参数可以重复。R55应急add-only补件并不改变R55原manifest，所以第一次修复后的正式包应同时选择已核R55与R54包。以后上一正式包已携带累计清单时，可只传该包。参数中的SHA必须来自实际验包回执，不能现场猜或用当前采样覆盖原pin。

新只读助手 `scripts/release-web-assets.py` 核输入ZIP的全包SHA、清单库存、路径、类型、模式、每项内容H与CRC，仅继承manifest登记的 `apps/web/dist/assets/` 内JS/CSS。相同路径与内容合并；同路径异H或已识别的静态/literal import、Vite依赖表、CSS依赖缺失则拒绝。旧index、service worker和旧离线清单不继承，不执行旧JS。

继承资产全部进入新release-manifest.files；`compatibility`另记schema1、输入版本/源码/ZIP与manifestH、资产行、增加及复用数，不包含本机构建路径。每次选择有限显式输入，累计最多4096个JS/CSS、32MiB；超限明确拒绝，不静默删文件。当前源码/构建关联、旧offline闭包及包内全部载荷校验继续保留。

## 停机前最后一门

新main的 `scripts/capture-managed-release.py activate` 在当前版本/角色核对后、创建activation控制目录及停止任何服务前调用助手的 `verify`。这条只读路径：

1. 核实际当前manifest的版本和H确实被新包compatibility引用；旧包身份不能换成任意更早版本。
2. 真实枚举当前assets目录内所有JS/CSS，包含原manifest未登记的应急overlay，要求每项在新manifest且新文件H/大小相同。
3. 保Root owner、非group/other可写、无链接、regular/nlink1条件；目录及文件前后稳定核对。缺件、异H、目录或文件竞争均在stop前失败。

这只是新增的main工具入口，不会让历史已固定SHA的sidecar自动获得新门。旧sidecar原件未修改；将来若选sidecar发布，必须在新purpose的独立资格审查中显式接入等价停机前校验，不得继续把历史四pin换标当成已核本规则。完整快照、隔离恢复、配置权限、健康及回退规则没有放松。

## 定向验证与范围

仅新增 `python scripts/test-release-web-assets.py` 五个真实ZIP/临时文件系统组：双包并集且不继承index/SW；错SHA/清单/依赖和缺显式输入拒绝；同H去重/异H拒绝；未登记overlay必须保留且有效校验只读；篡改、硬链和目录竞争拒绝。实际inherit CLI被调用，managed停机前位置另静核。文件系统组使用测试专有目录、显式关闭Root owner检查以便普通开发账号执行，不冒生产属主验收；生产verify CLI固定要求uid0。

旧打包组仅适配显式fixture上一包参数与新helper复制，原断言不降、不在本轮重跑。此维护不新增供应商模型、应用功能、R56构建/包或部署；内部编排费用未知，不写零。实际生产兼容恢复、用户连接错误及现场浏览器另由各自回执确认。
