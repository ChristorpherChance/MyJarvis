# 贾维斯 · 通用服务器授权工具

更新：2026-10-07。将三台服务器的专用授权脚本整理成可复用工具，适用于新增Linux服务器、新管理电脑和访问恢复。

**每台管理电脑生成自己的密钥；服务器只接收公钥。重复操作会复用本机已有密钥，并保留服务器原有授权。** 不需要把任何密码或私钥交给AI。

已新增[服务器权限选择器](服务器权限选择与授权.md)：普通登录、巡检、应用运维、完整管理需密码、完整管理免密码。当前三台superopen实测均已有完整免密sudo；权限按Linux账号生效，不按单把SSH公钥生效。

## 1. 工具与适用范围

| 文件 | 用途 |
| --- | --- |
| [server-access.mjs](../scripts/server-access.mjs) | 读取服务器清单、核对主机指纹、准备本机密钥、生成公钥授权包和验证登录 |
| [authorize-ssh-key.sh](../scripts/authorize-ssh-key.sh) | 通用Linux授权脚本，可直接传入公钥文件，也可生成每台服务器专用脚本 |
| [servers.example.json](../config/servers.example.json) | 三台已核实服务器的公开连接信息示例；新增服务器继续添加条目 |
| [专项测试](../scripts/test-server-access.mjs) | 密钥复用、指纹拒绝、脚本追加、限制保留与连接核对验证 |

管理电脑使用Node.js及OpenSSH客户端，可在Windows、Linux或macOS运行生成工具。服务器端脚本面向Linux，需要Bash、OpenSSH的ssh-keygen及常用系统工具；它不替服务器安装SSH或修改防火墙。Windows与Git Bash已实际验证，其他管理系统保留相同流程，仍需在对应系统实测。

不需要安装本项目的npm依赖。单独携带两个工具文件和清单，也能使用。Windows通过Node入口运行，不需要执行.ps1或调整系统脚本执行策略。

## 2. 第一步：填写服务器清单

可直接在[权限选择器](服务器权限选择与授权.md)中选择已有服务器或手动填写新服务器，补齐可信主机指纹后下载连接清单。下载清单的user是选定的授权账号，即新电脑以后要登录的服务器账号。也可复制[示例清单](../config/servers.example.json)为config/servers.json，保留需要授权的服务器。新增机器时填写：

| 字段 | 示例或说明 |
| --- | --- |
| id | i3-backup；唯一编号，只使用字母、数字、下划线或短横线 |
| host | 实际IP或域名，支持IPv4、IPv6和自定义SSH端口 |
| port | SSH端口，默认22 |
| user | 实际Linux登录用户，如superopen |
| hostname | 服务器实际主机名；填写后授权和连接均会检查 |
| fingerprint | 真实ED25519主机SHA256指纹，必须从可信渠道取得 |

首次安装服务器时，可在服务器本机终端读取：

~~~bash
whoami
hostname
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
~~~

清单只保存连接信息，不接受密码、私钥等额外字段。扫描到的主机公钥必须与事先填写的指纹一致；不自动信任首次扫描到的陌生主机。

现有三台示例信息来自已核对的[服务器清单](../服务器硬件与连接清单.md)。它们的IP使用DHCP，地址变化后更新host并重新准备；指纹不一致时先查清原因，不跳过检查。

## 3. 第二步：在管理电脑生成授权包

在项目目录运行，CLIENT换成这台管理电脑的标识，例如office-hp、home-pc、lenovo：

~~~powershell
node scripts/server-access.mjs prepare --inventory config/servers.json --output artifacts/server-access/CLIENT --client-id CLIENT
~~~

默认密钥保存在本机用户目录的.ssh/jarvis下；每台服务器使用独立的id_ed25519_jarvis_编号。现有密钥不会重新生成或覆盖；私钥与公钥不匹配、只剩公钥、指纹错误等情况会停止并说明原因。

Windows私钥权限限制为当前用户与SYSTEM；Linux/macOS私钥为600，新建私有目录为700。工具只整理选中的专用私钥，不修改全局SSH配置或整个.ssh目录。新建无人值守密钥使用空口令，并以本机文件权限保护。

生成目录包含：

| 文件 | 内容 |
| --- | --- |
| jarvis-编号.pub | 本机给该服务器的公钥 |
| authorize-编号.sh | 已填入用户、主机名和公钥的独立授权脚本；UTF-8、LF换行 |
| ssh-config | 本机独立SSH连接配置，使用jarvis-编号别名 |
| known_hosts | 已与清单指纹核对的ED25519主机公钥 |
| bundle.json | 生成时间、公钥指纹、连接信息与文件完整性清单；不含私钥 |

每次重新准备都会核对服务器指纹并更新本机授权包。工具不会自动在服务器添加授权，也不会安装软件或改变sudo权限。

## 4. 第三步：在服务器添加公钥

把生成的authorize-编号.sh交给能登录该服务器的人。用清单中的用户登录，在服务器终端执行：

~~~bash
bash authorize-编号.sh
~~~

专用脚本已经包含完整公钥，无需再粘贴公钥参数；也可以打开脚本，将其完整内容粘贴到服务器终端。不要使用sudo。

若使用通用脚本和单独公钥文件：

~~~bash
bash authorize-ssh-key.sh --user superopen --key-file jarvis-i3-backup.pub
~~~

已有访问权的管理电脑也能代为授权。下面以它已经具有jarvis-112连接配置为例，PATH替换为这台已授权电脑的配置路径，脚本文件来自新管理电脑生成的公钥包：

~~~powershell
scp -F PATH/ssh-config authorize-112.sh jarvis-112:~/jarvis-authorize-new-client.sh
ssh -F PATH/ssh-config jarvis-112 'bash ~/jarvis-authorize-new-client.sh'
~~~

这里传送的只有公钥授权脚本。首次没人能SSH登录的新服务器，用服务器本机终端，或由你在交互终端正常登录后执行；工具不读取或保存登录密码。

授权结果为status=added或status=already-present。相同密钥即使注释变化也不会再追加；已有from=、command=等访问限制保留，不另加不受限制的重复授权。已有文件末尾没有换行会补齐分隔，并使用锁避免同时写入。

用户或主机名不符、非法公钥、路径为符号链接、授权文件存在硬链接或所有权不符时会拒绝。正常执行仅追加当前账号的authorized_keys并整理其SSH目录权限，不覆盖旧公钥。

## 5. 第四步：验证与以后连接

回到生成授权包的管理电脑：

~~~powershell
node scripts/server-access.mjs verify --output artifacts/server-access/CLIENT
~~~

验证使用固定指纹、非交互免密登录和实际用户/主机名核对；只读，不修改服务器。结果保存为同目录verification.json。登录失败会显示具体问题，不回退为密码登录或关闭主机指纹校验。

以后直接使用本机生成的独立配置：

~~~powershell
ssh -F artifacts/server-access/CLIENT/ssh-config jarvis-112
~~~

也可使用npm run server:access -- prepare ...或npm run server:access -- verify ...。授权包中的ssh-config含本机绝对路径：换电脑需由新电脑重新生成，不能将旧电脑私钥复制过去。

## 6. 当前联想与新增机器的用法

当前联想已有三台专用密钥，位于.ssh根目录。使用以下命令复用原密钥；三台服务器不用再次授权：

~~~powershell
node scripts/server-access.mjs prepare --inventory config/servers.example.json --output artifacts/server-access/lenovo --client-id lenovo --identity-dir ~/.ssh
node scripts/server-access.mjs verify --output artifacts/server-access/lenovo
~~~

通用版另建授权包，不覆盖[原连接配置](../artifacts/server-connection-qa/ssh-config)。当前本机生成包见[连接配置](../artifacts/server-access/lenovo/ssh-config)、[授权清单](../artifacts/server-access/lenovo/bundle.json)与[实连结果](../artifacts/server-access/lenovo/verification.json)。

以后新增i3：把真实连接信息加入config/servers.json，再执行准备命令，给i3运行对应脚本，最后验证。其他管理电脑访问现有服务器：在那台电脑重新准备自己的包，将新公钥脚本授权到需要访问的服务器即可。

一台服务器可以授权多台管理电脑，家庭平台主备角色不受影响。这些授权仅用于SSH管理，不会自动赋予贾维斯成员身份、执行节点身份或额外sudo权限。

## 7. 检查与维护

~~~powershell
npm run test:server-access
~~~

专项测试使用隔离目录与临时密钥，实际执行密钥生成及Bash授权文件操作；连接边界使用隔离响应。现有三台服务器另做真实只读登录验证，报告见[工具验收记录](../artifacts/server-access-qa/report.json)。测试未向服务器添加新公钥。

本次7项专项测试全部通过，失败与跳过均为0。通用版已复用联想原密钥，101、112、116三台实际登录均通过，原私钥字节保持不变；三台无需重复授权。

管理电脑丢失或退役时，由仍有管理权限的人按该电脑公钥指纹移除服务器对应授权；不删除其他人的公钥。授权锁超时先检查是否有操作正在运行，确认没有后才清理遗留锁。工具不自动破坏旧锁，也不提供批量删除全部授权的操作。
