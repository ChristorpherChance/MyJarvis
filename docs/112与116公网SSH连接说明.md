## 在这台电脑怎么连接

本机SSH配置已安装，可直接使用：

    ssh ssh-112.ikvein.com
    ssh ssh-116.ikvein.com

也可用别名jarvis-112-remote、jarvis-116-remote。两端用户均为superopen，实际登录均为uid1000；112主机名superopen-ProDesk-i7，116为superopen-ProDesk-400-i5-6400。

**普通直连域名并加-p 2212或-p 2216目前不能使用。** 本机及日本独立探测均超时；网关本机端口可达。上游过滤的具体原因未证实，不能断言就是云安全组。

## 当前实际路线与配置

上述命令自动读取本机 ~/.ssh/config 中前置的Include，加载 ~/.ssh/jarvis-home-remote.conf，经现有广州SSH跳板jmp-superopen@8.163.127.192:22，再从网关127.0.0.1:2212（112）或2216（116）进入FRP，最终到各目标127.0.0.1:2222的新密钥专用sshd。

它们是本机SSH Host别名，不是保证任何设备都能裸连的公网端口。服务器主机身份固定在 ~/.ssh/jarvis-home-known-hosts，并启用严格主机校验；不能用关闭校验来代替这套绑定。

三项客户端私钥身份均只留本机：

- 广州跳板：~/.ssh/jarvis-cloud/id_ed25519_jarvis_gz
- 112：~/.ssh/id_ed25519_jarvis_112
- 116：~/.ssh/id_ed25519_jarvis_116

其他设备需具备这三项已授权密钥及等价profile/主机指纹配置，或另行登记该设备的新公钥。私钥正文不发聊天、不进Git，不包含在本文交付中。原 ~/.ssh/config 的完整旧字节保留在新增Include之后。

## 服务范围与撤销

112、116各新增且启用了jarvis-ssh-public.service与jarvis-ssh-tunnel.service，配置/程序分别在 /etc/jarvis-ssh-access、/opt/jarvis-ssh-access。新sshd仅监听loopback2222，禁止root、密码和交互式口令，只接受superopen公钥。

原LAN22、原业务、既有FRPC的配置指纹/PID保持；广州FRPS、nginx、SSH的PID及FRPS配置保持。没有修改云防火墙或FRPS监听规则。

如维护者需要撤销本次入口，仅停用两项新服务：

    sudo systemctl disable --now jarvis-ssh-public.service jarvis-ssh-tunnel.service

这只是回退方法，本次没有执行撤销，也不需为此重启原SSH或业务。112仍为R55；101冷备、软件工厂和暂停的自动跟进不变。本次是SSH接入配置，不是平台应用发布。

## 实际验证与保留边界

两节点均经当前跳板profile完成真实公钥登录，用户与主机名核对通过；原服务保持分别留证。116首轮因FRP配置省略auth.method而在任何写入前被拒，后继v2只兼容文档规定的默认token语义，原拒绝与审查保留。
