如何安排后续开发

  1. 在软件工厂项目中点击“项目监督”，查看已经完成的基线检查证据。接下来核对功能缺口，并安排完整集成测试、真实流水线和交付验证。
  2. 点击“安排任务”，填写明确的完善目标、验收标准、101 工作目录、Claude 执行器和费用预算。任务登记后不会自动开始。
  3. 确认节点和执行器就绪后，点击“开始执行”。持续开发仍受目标、轮次、Token、费用、重试次数与时限限制。
  4. 在任务详情查看执行事件、日志、验证回执和产物。额度或网络问题按已保存的有限恢复策略处理；登录、权限和未知错误需要管理员处理。
  5. 调整目标或验收标准前先暂停活动执行，再使用“调整边界”；修改后旧验收失效，依据与历史保留。预算可单独调整。
  6. 进程完成后进入待验收；检查独立测试证据并记录验收结论，验收通过后才生成交付记录。交付记录与实际部署分别管理。

Token 如何统计

  • 总账默认显示全部历史，支持今天、近七天、本月和指定日期；日期按服务器预算时区解释。
  • 可按模型、提供方、来源、场景、成员、项目和设备筛选。累计来自服务器全量汇总，不是当前页明细之和。
  • 对话、等待回应、知识解析、研究、模型验证、受控开发以及接入的独立调用都应留下计量记录。SDK 上下文压缩、缓存等返回的用量也需要记录。
  • 输入、输出、缓存读取和缓存写入分别展示，保留各提供方的原生口径。总 Token 使用提供方报告值，输入、输出与缓存分项不再叠加，避免重复统计。
  • 未返回或返回无效用量的调用记为“用量未知”，Token 留空；取消或中断不代表没有消耗，也不记成零用量或免费。本地语音等计算标明本地来源，实际不调用模型时记录为 0 Token，并可记录音频时长。
  • 软件工厂内部“用量”是上游原始汇总，金额币种未声明时保留原数并明确标记。它不直接累加到逐条总账；逐条接入需使用稳定来源标识去重。
  • 总账金额以 USD 报告或目录估算展示，未知价格单独列出。该金额不是网关账单，也不是付款凭证；供应商账单可另行导入核对。
  • 明细分页支持 25、50、100 或 200 条。“导出本页”仅导出当前页的计量元数据，不含聊天正文或密钥。

历史已保留的实际用量继续累计。没有原始调用回执的历史消耗无法准确回填，应保留未知，不推算为零，也不生成虚构账单。预算用于限制新的调用与续轮，已经发出的调用可能超过本地预留估算。

101 独立调用的持续采集

观察器每 120 秒检查一次实际 Claude 调用回执。对于持续运行的会话，按每条消息采集；该消息的计量回执稳定至少 90 秒后才入账，不需要等整个会话关闭。新增用量会持续增长，请在“用量统计”查看最新汇总，文档不固定累计数。

每条回执使用稳定的来源标识去重。贾维斯受控任务和观察器同时发现同一调用时，只记录一份消耗；不把整段会话反复累加。消息缺少有效用量时登记未知调用，Token 留空；回执变化或无法确认归属时保留待核对状态，不编造用量。中央只接收计量元数据，不上传独立会话的聊天正文。

可以在软件工厂项目的用量页检查来源、设备、调用时间和未知用量。在外部会话还没有稳定回执时，当前统计可能暂未包含该消息；没有可读回执的调用仍无法准确计量。总账中“金额未知”也不代表免费：部分已知 Token 的调用缺少可靠价格，需等价格配置或供应商账单核对。
