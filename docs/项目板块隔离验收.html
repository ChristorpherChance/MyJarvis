运行

在独立任务副本、普通账号运行：

npm ci
npx playwright install chromium
npm run build
npm run test:projects:browser
npm run test:projects:supervisor
npm run test:projects:controls
npm run test:projects:privacy
npm run test:projects:resume

Playwright固定版本由package-lock管理。浏览器未安装或前端未构建时先明确失败，不自动向生产回退。脚本不接受已有服务URL；使用专属临时HOME、环境白名单、createApp临时SQLite、显式独立运维/AI队列和禁用Python自动适配，Pi为禁止真实请求的替身。监听随机loopback端口并核对实例ID，浏览器仅允许同源，Node fetch仅允许fixture origin。这些是应用级隔离，不是操作系统级网络/文件沙箱。

启动前检查production目录、端口和权限边界，不能用 withPlatform 或直接写生产Store创建测试登录。日常 npm run dev 使用长期独立开发库，不是每次可删除的验收临时库。

浏览器通过不证明真实模型/101节点或软件工厂完整交付。project-workbench-r45.test.ts的签名agent子进程是本地Node协议fixture，不是供应商CLI。SSR、临时库合同、真实浏览器、生产历史与独立产品验收分开记录。

报告写入 artifacts/project-acceptance/<唯一attempt>/；保留首次失败及重跑，不将重复执行累计成新增场景。正常收尾逐项关闭浏览器/服务并清理自有临时库；父进程超时结束自有进程组并升级强制停止，强制中断不冒称已经执行正常清理或产品通过。

本地测试与部署分开

用户再次明确：先完成本地开发和测试，之后再部署。101实际接入与本机正式部署不是本地测试的前置条件。当前脚本始终创建自己的临时实例，不访问正式3140/3141，不因未部署停止本地项目/监管/接入合同和恢复测试。

后续新增的首次限流失败（浏览器密集操作超过300请求/分钟）保留；测试使用每250ms一个浏览器API调度和GET按服务端Retry-After最多一次重读，写操作不自动重试。不修改产品限流或把限流响应冒产品bug。签名控制恢复本地7项、工厂只读adapter与独立验收拒假边界32项通过；这些不是101当前工厂或完整交付结果。
