## 恢复范围

常用入口为总览中心、语音对话、大屏中心。工作创作包含统一收件、灵感研究、项目管理、开发监督、经验技能；知识学习包含知识接入、知识神殿、原文校对、学习计划；家庭生活包含家庭安排、记忆神殿、专属管家；系统运维包含设备管理、运行服务、运维费用、待办审批；系统设置管理模型、终端、监督、留存及审计。

菜单使用四字名称、分组展开、可收起导航与可搜索的完整功能目录。总览与大屏优先一页展示重要事项，小屏按内容自然滚动。对话保留左侧约 75% 视觉、右侧约 25% 内容控制与纯对话沉浸模式。

十套主题使用原型的独立造型及阶段驱动特效：光核战术、矩阵代码、复仇联盟、机甲驾驶、星际航行、火星基地、易经八卦、西方众神、水墨山河、百家书院。七类大屏为全域总控、家庭语音、知识故事、AI 研发、运维运行、灵感研究、经验技能。

详细功能对照见 [V15 功能核对表](parity-v15.md)。没有因简化菜单而删去原型模块。

## 需要走通的流程

1. 原话进入统一收件，保留来源与范围；去重后转成研究、经验、记忆候选或知识素材。
2. 研究明确问题、验收标准、有限预算，记录证据与反证；人工选方案后转成项目。
3. 项目关联设备上的开发副本，以里程碑生成依赖任务；监督显示租约、预算、重试、日志、技能引用及验收证据。
4. 开发完成后独立验收，打包可发布版本，申请审批；批准、执行、健康验收、恢复分别留痕。
5. 经验经过依据验证成为版本化技能；新任务记录所引用版本，后续版本更新不改写历史引用。
6. 知识来源动态登记，按授权、范围和接入模式检索；原件登记、解析、交叉校对、人工疑点裁决、逐页精校后发布原文基库。
7. 解读故事保留出处和版本；修订原文会标记派生故事与课程待更新；听读、测验、收藏和复习按成员记录。
8. 语音意图先生成选项并确认，个人记忆候选需确认；公共入口、个人聊天和私人记忆分开。

## 接口规则

类型与接口目录位于 `apps/web/src/demo/contracts.ts`。完整演示使用 `DemoProvider` 的命令入口；首批真实业务使用 HTTP 适配器，保留演示空间。V1 已实现五域与真实事件，剩余模块按 OpenAPI 状态逐个接入；原 `/api/` 接口继续运行。

请求、响应、错误、事件及核心数据定义见 [OpenAPI 契约](openapi-v1-planned.json)。当前路由状态及模拟适配器差异见 [接口状态说明](api-contract-status.md)：54 个操作已实现，95 个仍待接入；自动开发和研究执行器在就绪前明确拒绝执行。

写入命令采用 `{ commandId, expectedVersion, scope, payload }`。`commandId` 用于幂等，`expectedVersion` 防止并发覆盖；真实身份由服务端会话决定，客户端传入 profile 不能作为授权依据。成功返回 `{ requestId, version, data, events }`；失败返回 `{ requestId, code, message, details }`，页面保留原输入和可重试上下文。

| 模块 | 拟定资源 | 关键命令 |
| --- | --- | --- |
| 收件与研究 | `/api/v1/inbox`、`/api/v1/research` | 采集、合并、分流、证据、方案、人工决策、转项目 |
| 项目与监督 | `/api/v1/projects`、`/api/v1/tasks` | 副本、里程碑、依赖、租约、暂停、验收、打包 |
| 经验技能 | `/api/v1/experiences` | 验证、发布、版本、引用、停用 |
| 知识体系 | `/api/v1/knowledge/sources`、`books`、`stories` | 授权、同步、上传票据、校对、发布、修订、索引 |
| 家庭学习 | `/api/v1/learning`、`family` | 计划、进度、复习、家庭安排、个人记录 |
| 语音记忆 | `/api/v1/voice`、`memory`、`personas` | 识别、意图、确认、打断、候选、遗忘、声音偏好 |
| 运维发布 | `/api/v1/machines`、`services`、`operations`、`approvals` | 指标、发布审批、执行、验收、恢复、费用、备份 |
| 平台设置 | `/api/v1/settings` | Pi 模型能力、房间终端、资源策略、留存 |

实时信息统一使用有序事件 `{ id, sequence, at, actorId, domain, objectId, type, payload }`。聊天、任务、校对、部署和健康更新先用 SSE；房间双向音频通道在实际语音平台接入时单独实现。断线使用事件序号续订，刷新读取服务端当前快照。

后台继续以 Pi SDK 为智能编排基础。业务状态、授权、租约、预算和验收由贾维斯服务维护；Pi 提供会话、模型认证、资源与 Skill、工具调用、流事件及取消。LLM 的文字回答不能直接替代通过验收或审批的业务状态。

## 后台接入次序

先确认完整前端与状态规则，然后逐个接入真实接口：统一收件及经验 → 设备与服务查询 → 项目与开发监督 → 家庭身份和记忆 → 语音入口 → 动态知识及原文校对 → 学习和研究 → 发布恢复与费用。每个模块接入后保留演示适配器作为验收环境，并以权限、幂等、失败恢复及审计作为切换条件。

开发继续在联想 64GB；32GB 桌机承担预发布及恢复验证，48GB 桌机承担生产服务。高算力机器提供模型、语音和文档解析能力，i3 节点作为客厅、书房、厨房餐厅的语音入口。
