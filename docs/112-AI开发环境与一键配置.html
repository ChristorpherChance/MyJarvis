连接后直接开始

在已配置好 112 SSH 别名的终端执行：

ssh 112
cd /home/superopen/All-Projects/MyJevis
claude

这是本轮已就绪、有真实 Git 基线的独立源码工作副本，对应正式源码 a16a1eb9e0109bc31fefcb9325f74379529bd5cd。其中 node_modules 复用 /home/superopen/All-Projects/MyJevis-r53-closed-loop/node_modules，已核对相同 package lock；依赖并非全部物理独立复制。日常修改先阅读该目录的 AGENTS.md；正式部署目录与原件快照各有用途，不在原件树中启动旧项目。此前完整迁移目录和文件来源见112 开发迁移使用说明。

claude 使用现有全局默认通道。本次配置保留的默认为 JP-CCR (Codex订阅)，模型元数据为 gpt-6.1-sol[1M]；没有把默认切成 K3。

只在当前启动中使用 K3：

claude-k3

该入口调用 cc-switch start claude <K3选择器>，不切换全局默认。等价的显式入口为：

cc-switch start claude 'Kimi For Coding-699'

列出通道、查看帮助或打开 CC Switch：

ccswitch provider list --app claude
ccswitch --help
ccswitch

ccswitch 是 cc-switch 的别名。CC Switch 内主动切换默认通道会改变后续普通 claude 的选择；临时使用另一通道时可采用 start claude。首次进入项目如遇 Claude 原生目录信任提示，应依据自己是否信任该项目作正常选择；本轮保留既有权限和安全设置。

对话底部状态栏怎么读

状态栏从 Claude 官方 stdin 会话元数据读取数字，不读取 transcript 正文，也不查询模型或供应商余额。脚本及设置已安装到全局配置、CC Switch common 片段和各 Claude provider 的覆盖设置，使切换通道及 start claude 隔离启动沿用同一状态栏。

显示项 含义与边界
模型、通道 原生模型名称与当前通道标签；隔离 K3 启动使用其独立标签
ctx 当前请求的输入及两类缓存量 / 上下文窗口；字段不完整时保持未知
last in/out 最近响应的输入、输出 Token，不是累计用量
cache r/c 原生缓存读取、缓存创建 Token
CLI-est CLI 提供的本会话美元估算；缺失显示 ?，不等同供应商账单
native quota 5h/7d 只展示原生提供的额度使用百分比；未提供即 ?，不以本地五小时 Token 伪造套餐额度
CPU、RAM、磁盘可用 本机 /proc、文件系统数字采样；资源缓存最长约 15 秒，CPU 首次缺少差分时可为未知

脚本按可取得的终端宽度选择布局。真实原生交互 SSH 终端已观察通过：通过 tty=true 与 ssh -tt，逐步确认原生信任提示中的 Yes 后再按 Enter，实际下方显示：

k3[1m] | Kimi For Coding-699
ctx ?/1.0M | last in/out ?/? | CLI-est $0.0000
CPU ? | RAM 2.1G/45.9G | disk free 146.2G
cache r/c ?/? | native quota 5h/7d ?/?

该观察没有输入 prompt、没有新增模型调用；CPU 为首个差分采样未知，Token/额度未提供保持 ?。本次空会话显示的零 CLI 估算不改写下文那次真实 K3 调用的估算。随后两次 Ctrl+C 正常退出，exit 0。见原生终端观察回执与安全可见片段。这是本次实际终端布局的验收，不代表所有终端宽度或第二台机器已验收。

此前三次 Python PTY 尝试均停在项目目录信任提示，没有提交 prompt，不作为状态栏显示通过的证据。R2 的 projectTrustAccepted 标志曾仅表示发送了选择输入，没有证实原生提示已接受，现已按这个真实边界更正；成功依据是上面的后续实际交互观察，旧尝试回执继续保留。

私密摘要位于：

~/.local/state/jarvis-ai-development/session-summary.json

摘要仅含允许的会话标签、时间、Token、估算和资源数字，不保存 prompt、transcript 路径或正文。贾维斯展示时区分节点回执时间与真实资源采样时间；旧终端摘要不会因为重新读取就变成新的 CPU/RAM 采样。没有原生逐响应、可去重的账单证据时，不把这些摘要写成累计模型账单。

在贾维斯管理开发环境

R55 已上线，在“运维费用 → AI 开发环境”选择目标机器，或打开机器详情的“AI开发环境”页签。该入口面向已认证管理员，只操作绑定到本人可管理设备的可信节点；公司或只读设备不能配置。真实接口流程已通过，桌面与手机界面的视觉验收仍待完成。

  1. 选择已绑定的机器和环境模板，查看核心工具固定版本、当前观察时间及已有通道。
  2. “检查环境”读取工具和配置情况；缺项、未知版本及尚未配置会如实展示。
  3. “一键配置开发环境”安装或补齐固定工具，导入尚不存在的通道，并合并状态栏。现有同 ID 或同名通道的模型、认证、安全设置和默认选择保留。
  4. “刷新终端状态”读取最近的安全摘要。独立控制器约每 60 秒观察一次已绑定节点；该周期观察不调用模型，也不新建用户配置任务。
  5. 在环境运维记录查看排队、运行和回执。节点离线、模板版本或机器目标变化、超时等会显示阻断或待核实，不把等待当作成功。

控制器约每 10 秒写心跳，心跳有效窗口为约 30 秒；界面能力轮询约 10 秒、机器详情轮询约 5 秒，节点终端观察约每 60 秒一次，观察新鲜度窗口约 120 秒。资源卡另按采样来源和对应时间判断新鲜度。终端没有产生摘要时，“尚未收到状态栏采样”是正常的未知状态；不要为补一条记录而重复模型调用。

新机器复用模板的前置条件

一键配置处理的是已建立可信绑定的开发节点。仅有模板或一条普通 SSH 连接，不会让任意裸机自动进入管理范围。本轮实际验证目标只有 112，尚未完成第二台机器的端到端验收。

新目标需要兼容固定 linux-x64 构建的 Linux x86_64 环境、系统 Python 3，以及 passwd 中存在的普通开发账号（UID 至少 1000、真实且归该账号所有的 home）。管理员还需完成以下机器接入工作：

  1. 在贾维斯登记机器，核实实际 machine ID、hostname、node ID、地址与普通目标账号。
  2. 建立既有受限 SSH 运维通道及固定 dispatcher；通过真实机器身份与地址核对后，安装固定 AI 开发节点 wrapper。
  3. 将公开环境模板与该机器绑定，同时安装并固定 root 所有的模块、清单 SHA、公开 profile hash 和策略 hash。清单原文字节 SHA 与公开模板的规范化 hash 分别核对。
  4. 给独立控制器准备该模板的私密认证来源，确认队列、控制器心跳和机器观察正常，然后使用贾维斯配置入口。

中央控制器以 jarvis-control 普通系统账号运行，通过固定命令把配置 stdin 交给目标 wrapper；wrapper 再以目标普通用户运行 provision。API 不接收模型密钥，也没有任意 shell、路径或 argv 入口。目标安装工具不需要用户在日常 claude 前加 sudo。

私密模型配置保存在控制器的 AES-256-GCM vault 中，vault 与密钥文件受限，公开策略只含名称、模型 ID、是否有认证字段和固定绑定。传递采用私密 stdin，不把认证值放入命令行、URL、网页或日志。可移植字段只包含允许的模型和认证 env/model；不把 Windows 的 hooks、跳过权限设置、旧状态栏命令或私人会话带到新机器。

已有不符合固定版本的同名用户工具路径发生冲突时，安装器会安全拒绝覆盖并报告问题；应先核实该机器的原工具来源，再在已有授权范围内处理冲突。不要以删除用户目录或关闭安全门来冒充一键配置通过。

配置备份、回退与原件保护

配置过程有普通用户幂等锁，只在真正改变配置时产生同源私密备份，最多保留最近两次：

~/.local/state/jarvis-ai-development/backups/backup-<标识>/

备份包含修改前的 CC Switch SQLite 快照、相关原文件与 manifest。manifest 记录本机账号/home 绑定、相对路径和改动前后 SHA；配置事务失败时会回滚 SQLite，并在仍与自身写入身份匹配的前提下恢复已改文件。重复成功配置不会不断新增备份。

如需人工回退，应在没有并发配置任务时，依据同一机器的 manifest 与前后指纹恢复原配置，并做只读核对。当前固定 JSON 协议仅有 probe/configure/telemetry，未提供任意路径恢复命令；私密备份不能直接覆盖到另一机器，也不进入公开文档或 Git。

这两份是AI 终端配置备份，与贾维斯发布前完整恢复点的“保留最近两份”是不同对象。旧完整迁移原件仍在 /home/superopen/All-Projects/MyJevis/.migration-original/local，与上面的新 Git 工作副本分别保留。本轮终端配置不清理原迁移全文件快照、迁移桶或旧历史证据，也不运行原件中的 Windows node_modules、虚拟环境或旧生产入口。完整原件的保护边界继续按迁移说明执行。
