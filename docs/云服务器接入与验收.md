## 3. 监测如何运行

112发起固定SSH连接 → 云节点读取本机资源和允许的systemd单元 → 云节点用自己的Ed25519私钥签名 → 112核对来源、设备、路径和时间 → 中央既有Agent接口再次核验 → 保存资源趋势和服务状态。

没有新增公网端口，也不要求云服务器访问家庭内网。签名私钥保留在对应云节点，112持有公钥，不能替云节点伪造读数。

采样包括CPU、内存、磁盘使用率与余量、负载、运行时间。GPU和功耗没有真实来源时保持未知。资源读数每15秒更新；服务状态变化立即写入，不变时约30秒刷新，超过60秒显示观察过期。

云端采样器使用已有Python与OpenSSL，不安装完整贾维斯或Node运行环境。112的转发服务使用独立Node可执行文件，避免把监测账号加入业务账号组。

## 6. 后续扩展

1. 逐个关联云服务器上其他项目，配置应用级健康检查和明确授权的日志来源。
2. 若要让Pi使用日本模型接口，需要单独配置可达链路、供应商认证、模型和预算，再验证实际调用。现有CPA保持独立运行。
3. 云服务发布、重启等操作按固定程序和逐次审批接入，监测账号不会自动提权。
4. 101故障接替时，应为它生成独立监测SSH密钥并完成授权、同步节点登记与签名公钥。当前持续数据同步、自动接替仍未实现，不能把冷备宣称为热备。
