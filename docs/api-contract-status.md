首批包括统一收件、灵感研究、项目管理、任务交付、经验技能。36 个命令入口包括原目录的 34 个命令与 `tasks/commands/report`、`inbox/commands/keep-independent` 扩展。启动/恢复/重试执行器、AI 后台研究及取消、被动采集和记忆/资料分流仍待接入，相关请求明确拒绝执行。54 是接口处理统计，包含这种拒绝未就绪执行的入口，不等于 54 项完整运行能力；接口存在与执行就绪分别标注。

V1 在现有 `jarvis.db` 增加业务表、提交回执及事件表，保留原表、账号与 Pi 专用资料。原 S0 台账与 V1 数据分别保留，旧记录可在原控制台使用，Pi 查询工具可以同时查询两批真实数据。

沿用管理员 HttpOnly Cookie 会话与本机来源限制。服务器绑定 `server-admin`，请求不能指定或冒用成员所有者。`personal/private/family/company` 表示资料范围；家庭共享范围目前也只由管理员管理，尚不代表家人可以登录。

命令请求为 `{ commandId, expectedVersion, scope, payload }`。同编号同请求重放原回执；同编号不同请求拒绝。新记录版本为 0，修改使用目标 revision；旧版本写入返回冲突。对象、联动记录、事件、审计与回执在一个事务中提交，输出契约校验失败也回滚。

成功为 `{ requestId, version, data, events }`；失败为 `{ requestId, code, message, details }`。输入拒绝未声明字段。事件与审计保留必要元数据；报告证据保存在受权限保护的任务记录。S0 保持原负载、错误格式与 Pi SSE，不能只替换 URL。

单次 UTF-8 请求体上限为 128 KiB（131,072 字节），超限返回 413。字段长度与数组上限还需同时满足；大量记录应分批提交，当前接口不用于上传书籍扫描件。

`GET /api/v1/events` 为真实持久化 SSE，可按 `Last-Event-ID` 或 `afterSequence` 续订，会话失效与服务关闭时断开。`GET /api/v1/events/history` 支持分页回读事件。列表游标绑定身份、域与范围。

人工 report 保存来源、证据、状态、进度和产物声明，标记 `verification: unverified_external`、`executionDispatched: false`。本人验收记录核对说明；它不代表平台已运行测试、读取产物路径或完成实际部署。

契约与实现同步修正了三个返回类型：采集授权返回 CapturePolicy；研究立项返回 Project；任务打包返回 Task，固定包由 `/api/v1/releases` 查询。原话与历史引用继续保留。
