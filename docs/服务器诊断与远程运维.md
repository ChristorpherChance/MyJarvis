## 一、日常入口

正式平台：[贾维斯](https://cc-jarvis.ikvein.com/?mode=platform)。

| 需要做什么 | 页面位置 | 支持操作 |
| --- | --- | --- |
| 检查整台机器 | 设备中心 → 点击服务器 → 远程运维 | 整机诊断、重启服务器、关闭服务器 |
| 操作登记项目 | 运行服务 → 运行项目 → 点击项目 → 远程运维 | 项目诊断、启动、重启、停止 |
| 操作指定服务 | 运行服务 → 服务监测 → 点击服务 → 远程运维 | 固定服务诊断与已授权启停 |
| 主平台服务停止后恢复 | 提前打开独立运维入口 | 查看回执、启动112上的贾维斯服务 |

只限已登录的本人管理员。普通家庭成员、共享房间身份和仅选择“本人”资料不获得服务器操作权限。

这里提供服务器运维控制；图形桌面、鼠标键盘远控另行接入。业务数据库和项目文件查询也需要单独登记只读连接，当前诊断不读取私人数据。

## 二、整机与项目诊断

整机检查实际 CPU 使用率、线程数、负载、运行时长、可用内存与交换空间、磁盘容量和索引节点使用、只读挂载、网络接口、系统失败服务，以及登记服务状态和近期日志。

软件包只读镜像盘不参与容量告警。真实磁盘空间达到85%会提示注意，95%提示严重；可用内存不足10%、失败服务和只读挂载也会形成发现。硬盘 SMART 仅在工具及设备实际返回数据时展示，缺失保持未知，不能据此判断硬件健康。其他温度、风扇、电源传感器尚未接入。

项目诊断限定关联服务，并检查登记且已启用的网址健康规则。诊断完成与项目健康分开报告：HTTP异常会作为结果展示，不能因为诊断命令运行完成就报告项目正常。日志进行常见凭据遮盖，仅向管理员展示；模型只读取简要发现、状态和回执，不读取完整日志或恢复码。

## 三、启停与电源操作

操作先冻结目标、固定服务清单和影响，五分钟内明确确认才派发。同一任务重复提交不会再次执行；连接中断后只查询持久回执，不自动重发操作。目标地址、关联关系或授权改变，需要重新准备。

| 状态 | 实际含义 |
| --- | --- |
| 待确认 | 尚未派发，可以取消 |
| 已排队 / 执行中 | 独立控制器正在处理，不能当作完成 |
| 已提交 / 正在核实 | 指令已接受，仍在观察实际状态 |
| 已核实 | 服务状态已验证；项目启用健康规则时还需网址检查通过 |
| 执行失败 | 未通过执行或恢复检查，应查看原因 |
| 结果待核实 | 连接或回执不完整，不重复执行 |
| 已断联 · 电源未核实 | 关机指令被接受且SSH已不可达；物理电源状态仍需人工核实 |

服务重启核对实际状态及新的启动时间；停止核对已停止状态。重启服务器核对新的系统启动标识，再核对登记服务预期状态，允许服务启动恢复时间。这里只检查登记服务，不代表全部业务数据完整性已验收。

项目启停改变当前服务运行状态，不修改系统开机自启动策略。项目登记的暂停状态及自动健康检测开关可另行管理，实际进程状态以服务观测和操作回执为准。

关闭服务器会列出登记项目中断影响。**机器启动暂不支持**，关机后需人工或云厂商控制台启动。原有机器管理中的其他唤醒接口，不代表这些服务器的开机已接入验收。

## 五、语音指挥

本人管理员使用对话中的事项理解，或管理员语音入口，可说：

- “贾维斯，诊断一一六服务器。”
- “重启116上的MyFamily项目。”
- “重启112服务器。”
- “关闭广州服务器。”

贾维斯会读出确切目标、动作和影响，再等待本次口头选择或页面确认。诊断同样可通过语音确认；页面诊断按钮可直接提交只读检查。

目标不明确会要求明确编号和项目；未登记的项目名称不会降级成服务器重启。“不要重启”“如何重启”和日常“检查孩子作业”等不会直接变成服务器操作。口头确认必须来自当前会话的真实识别结果；后台使用与页面相同的冻结目标和防重复执行规则。

Pi SDK提供对话理解与只读进度查询，机器动作由固定运维流程执行。模型不能临时编写服务器命令，不能替你批准操作。模型、ASR及TTS仍需完成各自配置和实体语音验收。

## 六、独立恢复入口

公网：[独立运维](https://cc-jarvis.ikvein.com/control/)。局域网：[112独立运维](https://192.168.10.112:3142/control/)，需要本机信任项目局域网证书。

管理员在远程运维页点击入口，获得十五分钟独立会话。也可点击“查看运维恢复码”，私下保存，主平台服务不可访问时使用恢复码登录；页面默认遮盖，六十秒自动收起，读取接口禁止缓存。退出独立运维会使该独立会话失效。平台登录和独立会话分别管理，后者到期自动失效。

独立控制器与域名连接不依赖主平台服务，保留独立日志和持久回执，能够启动停止后的112平台。通过独立入口产生的任务会在平台恢复后归入同一管理员历史。

**独立进程仍在112这台机器上。** 重启112时该进程也会中断，机器回来后继续核实磁盘中的回执；关闭112、网络断开或硬件故障时，它不能继续提供在线控制。若广州网关关闭，公网入口也会中断，可改用仍在线的局域网入口。真正跨机器常在线的恢复控制面是后续阶段。

## 七、部署与验收

应用版本 `20261008-remote-operations-r1`，112运行，101安装同版并保持冷备。维护账号负责安装；日常遥测仍是只读账号，新操作使用独立 `jarvis-ops` 账号、强制SSH命令、固定sudo包装器和服务器本地清单，不授予任意Shell。主平台只能写操作请求、读结果；控制器只处理固定操作，不能读取平台数据库。

| 记录 | 内容 |
| --- | --- |
| `artifacts/remote-operations/provisioning.json` | 五节点固定操作、两控制器和公网入口安装 |
| `artifacts/remote-operations/dispatcher-verification.json` | 八项隔离测试、真实临时服务启停与重复执行验证、清理恢复 |
| `artifacts/remote-operations/api-tests.log` | 冻结目标、权限、回执持久化、独立结果导入、语音确认及原有项目接口回归 |
| `artifacts/remote-operations/live-verification.json` | 实际整机与项目诊断、独立入口和部署状态验收 |
| `artifacts/remote-operations/ui/report.json` | 页面、确认取消、独立入口、主题及移动端检查 |

电源命令以隔离模拟验证，**没有为测试重启或关闭任何生产服务器**。真实启停验证使用已清理的临时服务，未修改现有业务项目。验收报告以实际生成结果为准。

本次验收已通过：五台整机和两个项目的真实诊断、独立入口诊断、八项隔离测试、四项后台回归、新增页面七项检查、原有监管页面十四项检查和域名浏览器八项检查。32个服务与13个项目也完成回归；两台平台节点269个构建文件一致，112运行、101冷备。116在收尾时短暂失联，随后恢复，最新诊断和监管均已核验；中断请求保留待核实，不自动重复执行。

接口已补入 `docs/openapi-v1-planned.json` 的 `/api/runtime/remote-ops/*`。包含能力、历史、准备、确认派发、取消、独立会话和恢复码八类接口；这些运行期接口与既有 `/api/v1` 业务契约分别维护。
