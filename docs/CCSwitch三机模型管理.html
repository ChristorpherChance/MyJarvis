CC Switch 三机模型管理

在112贾维斯中管理101、112、116各自的Claude Code模型配置。

进入模型管理

在112贾维斯打开 运维费用 → 终端模型，对应路由 operations/cc-switch。也可以进入某台机器详情的 AI 开发环境，管理该机器的配置。

选中101、112或116后，页面读取该机器的CC Switch配置，展示当前启用项、API地址和各角色模型。刷新会重新读取机器上的实际状态。机器连接失败时显示错误，不用缓存结果冒充当前状态。

这是Claude Code终端模型管理，与贾维斯自身的对话模型设置分别管理。操作需要管理员本人身份。

平台常规源码现位于112的 /home/superopen/All-Projects/MyJarvis。本轮独立开发副本位于 /home/superopen/.local/share/jarvis-development/cc-switch-center-20261020；历史资料里的MyJevis名称保留当时记录，不作为新的开发入口。

切换模型

在目标配置上点击 切换到此配置。操作成功后，检查当前启用标记，再新开Claude Code会话使用。已经运行的会话可能继续使用启动时的配置。

每次操作明确绑定选中的机器。对112切换不会自动改101或116；需要调整另外一台时，先选择那台机器。

新增或编辑配置

点击 新增模型配置，或在已有项上点击 编辑。可以维护名称、API地址、主模型，以及Opus、Sonnet、Haiku、Fable和子代理的模型覆写、认证方式与API Key。主模型和角色覆写填供应商实际支持的模型标识。新增配置时，角色覆写留空会沿用主模型；填写明确值则保留该角色的独立模型。

API Key使用密码输入框，平台不回显已有明文。新增时填写对应服务的密钥；编辑时 留空保留原密钥，填写新值才替换。密钥随本次请求发送到目标机器，不放入浏览器持久存储或公开操作记录。

保存只修改选中机器的配置。新增项会进入该机CC Switch列表；保存后可按需要切换到它。配置写入成功与供应商实际可调用是两项结果，密钥额度、上游可达性及模型可用性仍以真实调用为准。

删除配置

非当前项可以点击 删除，确认框会标明目标机器和配置。当前启用项不能直接删除：先切换到另一项，再删除原项，避免留下没有当前配置的状态。

删除移除的是选中机器上的这项CC Switch配置，不会注销供应商账号或撤销上游密钥。

并发修改与本机终端

平台操作使用读取时的配置修订。若另一页面或本机终端先修改了配置，平台会拒绝过期写入。遇到修订冲突，刷新后核对最新内容，再重新编辑，避免覆盖另一处的修改。

三台机器原有本地入口继续共用各自的配置：

ai          # 本机模型菜单
ai manage   # 本机CC Switch管理

平台和本机终端读写同一台机器的CC Switch资料，没有另一份需要手动同步的模型清单。多台机器的配置仍各自独立。

116的现有网关

本功能管理116的Claude Code与CC Switch配置。116现有CCR网关、广州Kimi网关地址及其转发服务保持原有职责，不通过这个页面修改网关服务配置。Kimi CCR配置继续使用已经登记的网关地址；切换终端模型不代表调整公网域名或转发链路。

验证与记录

本轮API及合并回归27项通过，原生CC Switch隔离适配18项通过；UI组件边界、最简新增配置的角色沿用、明确角色覆写、类型检查和API/网页构建通过。增强后的三机连接已实际核对读取、新增、编辑、删除、Kimi切换及恢复，临时项已清理，已有密钥未回传。

API初次回归有4项失败，装配与合同生成修复后原断言保持、27项复验通过；初次结果继续保留。以上是本轮限定范围验证，不代替正式页面上线后的使用验收。
