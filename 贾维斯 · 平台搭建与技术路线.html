1. 已确认的建设方向

当前机器确认为 Windows 11 联想，Ryzen 7 PRO 4750U，8 核 16 线程，系统可见内存约 63.4GiB。本轮读取时 D 盘可用约 63.5GB，日后以实时采集为准。Node 24.15.0、npm、Git 与 Docker 可用。

部署角色采用最新确认方案：联想 64GB 开发与本地测试 → 32GB 桌机预发布 → 48GB 桌机生产。高算力机器负责语音、文本推理与批处理接口。i3 房间终端先客厅、后书房；厨房餐厅先测试噪声，卧室暂不接入。开发执行器使用独立工人节点，生产中枢负责管理与监督。

本轮仅建设当前开发机，没有更改其他机器系统、访问云服务器或暴露公网入口。

2. 为什么选择这条技术路线

用户指定 Pi 作为后台 SDK 基础，因此平台核心使用 TypeScript，直接调用 Pi；前端使用 React，HTTP 使用 Fastify。重型语音、OCR、向量索引放在独立工人服务，以接口连接，不让中央管理后台承担 GPU 工作。

官方当前包为 @earendil-works/pi-coding-agent；本工程锁定 1.0.2。旧 @mariozechner/pi-coding-agent 已弃用。选型依据是 Pi 官网、SDK 文档 与 1.0.2 源码。

需求 复用 Pi 贾维斯负责
模型连接 ModelRuntime、模型目录、凭证接口 管理配置与可用状态
对话 createAgentSession、SessionManager 身份、会话归属、页面历史
实时状态 subscribe、text_delta、终态 HTTP 流、异常状态、断流处理
停止 abort、dispose 权限检查与页面停止按钮
通用技能 资源加载与原生 /skill 指令 审核、业务范围与版本
业务工具 customTools 权限过滤及业务数据来源
开发监督 后续可使用 Pi 执行会话 工人注册、租约、预算、验收、审批

禁止默认加载用户全局扩展或工作目录上下文；家庭对话不默认获得命令行、任意文件写入和全盘读取能力。Pi 是代理基础，不能替代身份、业务真相和交付验收。

管理者账号没有因角色而获得全家私聊权限。当前尚无家人独立账号，不能通过选择一个档案冒用成员身份。模型未配置时，不生成假回答。没有执行器时，不显示虚构自动进度或声称持续开发。

4. 存储与启动

开发底座使用 SQLite WAL、迁移版本和事务，业务对象与 Pi 会话有明确引用；每个会话单独记录运行状态。管理员密码经过加盐哈希；登录 Cookie 为 HttpOnly、SameSite Strict，接口校验登录、输入与请求来源。

正式生产前采用 PostgreSQL，建设迁移、恢复验证与访问入口。当前 SQLite 实现只作为本机开发底座；未实施的 PostgreSQL 不能作为当前部署能力。

构建后从 http://127.0.0.1:3140 使用；首次自己设置管理员密码，再选择 Pi 模型并保存凭证。模型凭证走 Pi 专用配置，不回显浏览器，不进入日志或普通设置表。当前只允许监听本机；手机、房间终端和外网入口随身份与 TLS 建设后接入。

业务库和 Pi 资料位于 .jarvis，不进入源码版本管理。备份工具创建业务库快照并复制 Pi 资料；停止后端后执行，恢复先在独立目录演练。磁盘可用空间有限，当前不下载本地大模型、整库书籍或巨型镜像。

5. 继续建设的推荐顺序

最新开发策略调整为 前端与接口契约先行、真实后台分模块接入。当前 S0 已完成的真实底座保留；下一步优先将已确认的 V15 全量页面转为正式前端，完成业务流程验收，再推进下方真实服务阶段。

下一步 交付与验收
F1 · 页面与边界 全量页面清单、导航、十主题、管理端和各大屏；每项操作都有明确入口与结果
F2 · 接口契约 OpenAPI、共享类型、权限、分页、错误、事件、业务状态机；不让页面自行猜接口
F3 · 模拟流程 独立演示数据，明确演示标识；正常与异常流程可重复运行、重置，不写真实库
F4 · 逐模块接入 模拟与真实实现使用同一契约；经过相同流程验收再替换，避免重新改整套前端

模拟验收需要覆盖：对话的识别、思考、回答与打断；开发任务的派发、执行、阻塞、重试、预算与验收；原件上传、OCR 疑问、多轮校对、人审、发布与课程；家庭身份和私有记忆的访问边界。异常样例包括空数据、加载、超时、断线、失败、取消、无权限与验收不通过。模拟流程验证界面与业务设计，真实模型质量、语音延迟、GPU 能力与部署可靠性仍以实际接口验证。

  1. S1 · 设备与开发监督：32GB 预发布部署、设备 Agent、服务清单、执行器注册、任务租约、事件回传、预算、失败停止和交付验收。先接一个真实项目，验证不会无限空转。
  2. S2 · 家庭语音：成员身份、房间会话、STT/TTS、唤醒与打断。高算力接口优先处理实时语音；客厅稳定后接书房。
  3. S3 · 双神殿：原件不可变、识别版本、疑问清单、人审、发布版本、证据索引、人物故事与学习规划；个人记忆与共享知识分离。
  4. S4 · 研究与经验：灵感收件、资料证据、研究任务、经验去重、验证及 Skill 发布，多终端统一采集。
  5. S5 · 正式上线：PostgreSQL 迁移、权限验证、备份恢复、语音负载与生产健康检查；在 32GB 验证后发布 48GB。

阶段顺序可按实际使用优先级调整。每个阶段以真实链路验收为准，原型中的模拟内容不作为运行事实。

6. 验收口径

首轮检查登录与首次初始化、请求来源、真实设备来源、登记与关联校验、重启持久、人工交付说明、会话归属、模型缺失提示、流式状态及取消，以及业务库备份恢复。

自动化测试使用临时数据库；运输层测试使用明确的测试替身，运行应用使用真实 Pi SDK。真实模型回答还需选择模型和有效凭证，未执行付费模型请求就不声称已验证推理效果。

本轮 11 项自动化回归通过。新增故障验收覆盖：首条写入失败后仍可重试、回答无法保存时返回明确终态、关闭服务时取消活跃对话；未保存文本在页面留存供复制。依赖审计当前为 0 已知漏洞。前端构建与类型检查通过，浏览器验收使用独立临时数据，不替管理者设置真实密码。

高算力接口可沿用 Pi 官方 models.json 的 OpenAI 兼容配置：放在本工程专用 .jarvis/pi/agent/models.json，重启后从模型目录选择。浏览器填写自定义地址尚未实现，实际 GPU 服务、地址与模型能力需到接入阶段确认。参见 Pi 模型配置说明。
