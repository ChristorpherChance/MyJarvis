2. 账单准备与核对

先把供应商导出的明细整理为标准CSV或JSON数组，填入供应商、账户标识、账单编号、币种、来源文件及账期。页面日期按北京时间处理，结束日期不包含当天；明细时间需携带ISO时区。

id,at,model,amount,usageId,providerRequestId,totalTokens
line-1,2026-10-06T08:00:00+08:00,实际模型名,0.150000,,供应商请求号,12

金额使用十进制字符串，支持负数退款和抵扣，最多6位小数。CSV必填id、at、model、amount，其余列可留空。单次最多2000行，页面文件上限500KB，导入HTTP请求上限1MiB。JSON方式使用同样字段。

流程：预览 → 确认冻结的内容 → 导入 → 按明确用量ID核对 → 人工处理未匹配项。页面可以查阅本账期的实际用量，查看原币种金额、估算USD、差异及核对记录。账单列表支持继续加载更早记录；详细表格先展示100行，人工核对仍可选择全部明细。

只有明确填写且与供应商、模型、账期一致的本平台usageId，才会自动关联实际SDK用量。供应商providerRequestId单独保留，不猜测它等于本平台usageId。人工关联或解除需要说明；同一用量不能被两条账单重复占用。作废需要原因，保留原账单和核对证据，不能用重新导入覆盖已作废账单。

提交编号和内容指纹用于重试去重，版本防止覆盖他人的核对结果。重复请求返回当前权威记录，不恢复旧版本。审计记录保留动作、版本、关联说明或作废原因，不重复复制整个账单。

USD账单与USD估算费用比较；CNY、EUR保持原金额，明确显示不可直接比较。按币种分别汇总，最近500张的概况会标明是否截断。使用整数微单位计算账单金额，避免浮点累积误差。原SDK使用账本、预算预留与未知费用保持各自实际含义，导入不会修改它们。

当前实现标准明细导入与核对。供应商API自动下载、账单真伪认证、自动换汇和付款尚未接入。

3. 日志来源配置

先登记真实设备和服务，配对节点并授予service-logs能力。在中央配置来源，明确同意后开启。来源绑定固定机器、服务和绝对文件路径；不能从上报接口临时指定任意路径。

已有配对票据接口POST /api/v1/execution/tickets可用capabilities:["service-logs","telemetry"]开启两类采集能力；同时承担开发执行时保留原固定执行器ID。页面生成票据的逗号分隔输入框也填写这些能力名。票据仅返回一次，放入节点私有配置，不写入日志或项目文档。

{
  "expectedVersion": 0,
  "logSources": [{
    "id": "jarvis-api-log",
    "serviceId": "实际服务ID",
    "machineId": "实际机器ID",
    "path": "D:\\Jarvis\\logs\\api.log",
    "enabled": true,
    "consent": true,
    "retentionDays": 7
  }],
  "hardwareSources": []
}

更新时使用GET读到的当前version作为expectedVersion，PUT提交完整配置，不是增量合并。来源ID不能重复，每类最多100个。公司电脑或只读设备不允许采集服务原始日志。

节点本地还必须明确允许同一个文件；中央配置不会自行添加本地授权目录：

{
  "workspaceRoots": ["D:\\Jarvis\\logs", "D:\\Jarvis\\metrics"],
  "serviceLogs": [{
    "sourceId": "jarvis-api-log",
    "path": "D:\\Jarvis\\logs\\api.log"
  }],
  "hardwareReadings": []
}

这是已有节点配置的扩展片段，保留原apiUrl、machineId、配对身份和templates。节点需要升级运行器；已有已配对节点若没有service-logs能力，需重新签发所需能力并配对。固定文件须位于本地允许目录，符号链接和越界路径拒绝读取。

node --import tsx apps/agent/src/index.ts --config D:/Jarvis/node.json

默认从新配置文件末尾开始跟随，避免初次上传整个历史文件；明确设置fromStart:true才从头读取。节点每轮读取最多64KiB，仅上传完整UTF-8行，超长行整行跳过；中央确认后才推进文件偏移。初始流编号在发送前保存，文件轮转或截断使用新流编号；断线重试按流和偏移去重。

客户端和中央都执行脱敏，覆盖密码、令牌、私钥、Cookie、Authorization等常见形式。日志页面显示服务器接收时间，不将它冒充日志原始事件时间。签名证明是当前授权节点的上报，不能证明节点上的应用绝无篡改。

每来源最多保存5000行，留存1–30天；取消来源不会延长既有过期时间，缩短留存会及时清理。中央每30秒清理一次。去重回执保留30天，仅含必要指纹及回执信息。

4. GPU与功耗读数

中央已有CPU、内存的实际操作系统采样。新增GPU与功耗只接受当前授权来源、匹配配置版本和新鲜采样时间的签名节点读数；未配置、过期或缺失保持未知，不能根据CPU估算瓦数。

中央hardwareSources示例：

[
  {"id":"gpu-sensor","machineId":"实际机器ID","field":"gpuPercent","adapterId":"实际GPU采集器ID","enabled":true},
  {"id":"power-meter","machineId":"实际机器ID","field":"powerWatts","adapterId":"实际电表采集器ID","enabled":true}
]

同一机器的同一指标只能有一个当前来源。节点需要telemetry能力，本地hardwareReadings示例：

[
  {"sourceId":"gpu-sensor","field":"gpuPercent","path":"D:\\Jarvis\\metrics\\gpu.json"},
  {"sourceId":"power-meter","field":"powerWatts","path":"D:\\Jarvis\\metrics\\power.json"}
]

分别由真实采集器生成小型UTF-8 JSON文件，单文件上限4096字节：

{"value":36.5,"unit":"%","adapterId":"实际GPU采集器ID","measuredAt":"当前采样ISO时间"}
{"value":42.3,"unit":"W","adapterId":"实际电表采集器ID","measuredAt":"当前采样ISO时间"}

GPU范围0–100，功耗非负且小于10000000W；单位、adapterId与中央配置必须对应。允许最多30秒旧读数或10秒时钟超前，真实0值可以入库，过期不会变成0。坏文件或缺失来源不影响普通CPU/内存心跳。

现有7天原始采样、90天汇总、趋势时间窗口和空值策略继续适用。Pi运行趋势只读工具也显示实际GPU/功耗或未知值。

本轮完成文件读取、签名传输、来源校验、存储和趋势展示，尚未替实际机器安装GPU传感器或智能电表采集器。

具体严格请求和响应字段见OpenAPI。标准账单接口直接返回对象；/api/v1采集接口继续使用已有data响应封装。
