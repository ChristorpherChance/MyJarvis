两种通用监管方式

当前项目情况 监管方式 推进顺序
需求和代码仍在持续完善 持续开发 明确目标 → 持续开发 → 独立验证 → 问题修复 → 交付维护
已有主要成果，需要检查是否达标 测试验收 全面测试 → 核对产物 → 修复复验 → 交付验收 → 自动运行

同一项目可以变更计划或建立后继计划。每次变更保留版本、原因、原任务与运行编号。当前阶段是管理安排；执行中、失败或结束来自实际任务回执，不能通过修改计划得到“已完成”。

软件工厂本轮执行

  1. 全面测试：针对当前主线隔离快照，检查全部现有适用单元与集成测试、覆盖率、30 组原型回归、构建、类型与文档规范；同时检查打包、解包、新环境启动和接口回读。
  2. 核对产物：从客户原始需求开始检查 PRD、需求追踪、概要设计、详细设计、所有页面及子页面原型、代码和测试是否使用同一需求版本，是否存在遗漏或关联错误。
  3. 修复复验：区分产品缺陷、测试断言问题、环境问题、缺失产物及尚未实现功能。记录问题、影响范围、对应需求、源版本、修复任务与复验；只有新证据能关闭问题。
  4. 交付验收：从零创建客户项目，验证各阶段产出、产品文档和软件包、安装启动、数据备份恢复、版本发布与变更后的影响和复验。
  5. 自动运行：检查各阶段 Agent 与子 Agent 的迭代评测、版本晋升和回退，以及连续开发、限额换路由、异常恢复、长时间观察和全过程追溯。

原来的 74 项目标、148 条验收要求和阶段依赖继续保留。上述五步是简洁汇报入口，不改变原始验收分母。旧 R22 候选副本用于历史对照，不替代当前主线结果。
