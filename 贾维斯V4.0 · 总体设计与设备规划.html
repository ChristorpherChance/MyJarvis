1. 项目定位与版本关系

贾维斯是面向本人和全家的数字管家。它统一了解机器和项目、监督开发任务、积累经验与技能，同时提供家庭聊天、语言陪练、知识学习和生活信息服务。用户通过网页、手机、大屏或语音使用同一套能力。

1.1 五项核心职责

职责 目标 典型表达
家庭陪伴与学习 为不同家人提供适合其年龄、基础和偏好的交流、语言练习、知识讲解 “陪我练十分钟英语。”
生活信息服务 查询天气、信息，提供烹饪建议和健康信息辅助 “这些食材怎样做更合口味？”
机器与项目管理 掌握设备状态、服务、项目位置、开发环境和当前工作 “家里哪台机器正在开发哪个项目？”
开发任务监督 跟踪 CC/Codex 等执行器，按目标持续推进、验证和汇报 “昨晚的任务推进到哪里了？哪些问题需要我处理？”
经验与技能积累 收集各机器上的问题、经验教训和通用 Skill，并在后续任务中复用 “把这次排查过程交给贾维斯整理。”

1.2 与历史文档的关系

  • 贾维斯 · 实现方案：保留最初目标和部署步骤，具体命令使用前仍需核对版本与环境。
  • 贾维斯 V2.0 · 完整方案（管家版）：保留资产台账、可观测、执行通道、Runbook、自愈和后台任务的完整能力目标。
  • 贾维斯 V3.0：保留私有组网、云端与本地协作、分阶段验收和降低起步成本的方向。
  • V4：补齐设备数量与真实用途，增加家庭服务、跨机器项目管理、经验与 Skill 管理、持续开发监督以及统一大屏。

V4 对之前“只用现成工具拼出编排核心”的想法作了进一步收敛：需要一层轻量自研 Jarvis Core 来保存统一业务状态；模型推理、执行器和工作流仍使用现有能力。

3. 设计原则与总体架构

3.1 设计原则

  1. 统一状态：网页、大屏、手机和语音查询同一套机器、项目、任务、经验、技能与家庭档案。
  2. 根据事实汇报：状态带来源和时间；任务完成要有验收结果与产出物，未知信息明确标为未知。
  3. 云端推理与本地能力协作：复杂推理使用合适的云端模型；本地承担可胜任的感知、处理与执行任务，保留本地/云端选择权。
  4. 隐私模式可落实：选择隐私模式后，相关内容不进入云端推理或云端语音链路；必要时报告能力降级。
  5. 常驻服务与计算节点分离：低负载的控制、记录、查询与监控保持在线；重任务按需使用 GPU、E5 或其他节点。
  6. 目标驱动的持续工作：监督器依据任务目标、验收、预算与停止条件推进工作。
  7. 按身份开放能力：家庭成员、个人项目、公司项目和系统运维具有不同的数据范围与执行权限。
  8. 每步可验收：先实现真实的小场景，再扩大设备和任务数量。

4. 全部机器的安排规划

4.1 10 台 i3 的建议分工

编号为规划编号，后续绑定实际主机名、序列号和网络身份。选择常驻机时，优先考虑稳定性、磁盘健康、散热、网络和实测整机功耗。

编号 角色 建议运行内容 开机策略
i3-01 管家控制与入口 Jarvis Core、网页入口、n8n、任务派发与审批控制、WOL 控制、离线事件暂存 常开
i3-02 轻量数据与应用服务 业务状态库、Gitea、适量知识检索服务、基础指标与 Uptime Kuma、备份结果检查 常开
i3-03 基础服务冷备 可恢复的部署环境；定期恢复 i3-01/02 的备份，故障时人工接管 默认关闭，演练时开启
i3-04 轻量测试 新服务试装、配置验证、小项目测试；与日常服务分离 按需
i3-05 轻量任务执行 中小 Agent 任务、脚本、文档生成、轻量 CI；起步限制并发 按需，有任务时保持在线
i3-06 经验与资料整理 文件索引、经验整理、Skill 入库与同步、无需 GPU 的资料处理 按需或定时
i3-07 家庭办公 文档、浏览器、学习和远程访问，家人按权限使用 使用时开启
i3-08 大屏与固定语音入口 浏览器大屏、家庭控制入口；有合适音频设备后接语音 按家庭需求；屏幕可单独休眠
i3-09 机动备用 故障替换、临时项目或未来扩展 默认关闭
i3-10 机动备用 故障替换、实验或按实际价值转作其他用途 默认关闭

基础服务先控制在两台常驻 i3 内。6100T 的 CPU 能力有限，内存容量不等于可无限增加服务和并发；数据库、索引、日志保留和工作流都需按实际负载调整。

01/02 之间存在依赖，不能将两台机器简单视为高可用集群。主数据服务失效时，控制端应报告降级，暂存可保留的事件，并通过冷备和备份恢复。大屏终端常开时是额外的常开设备；其语音能力也要单独验收。

有学习需求时，可从测试与备用机中选三台搭建独立集群实验环境。日常任务先使用简单、可恢复的部署结构。10 台小机的内存与磁盘是分散资源，需要任务调度或显式分布式软件才能协作，不能自动合成单机资源。

5. 身份、家庭档案与权限

5.1 使用者档案

每位使用者有自己的身份、偏好和数据范围，不按家庭角色推定兴趣或学习水平。

使用者 默认服务方向 可配置内容
本人 家庭服务、项目管理、任务监督和运维控制 项目范围、执行授权、通知、预算、模型与隐私模式
妻子 聊天、语言练习、知识学习、个人事项 目标语言、水平、兴趣、纠错方式、回答风格
儿子 年龄适合的语言与知识学习、兴趣交流 年龄阶段、学习目标、练习方式、家长可管理的使用规则
爸妈 聊天、天气、烹饪、生活与健康信息辅助 大字、简洁回答、语音速度、口味和经本人选择记录的偏好

个人学习进度、聊天记忆、健康记录按个人权限保存。家庭共同日程、共同待办和共享知识进入家庭共享范围。公司项目与个人项目分别标记，上传和检索都遵循项目的可共享范围。

5.2 身份与权限的关系

  • 账号负责确定身份和可访问范围。
  • 声纹可帮助选择档案或提示使用者，但不能成为敏感查询和系统操作的唯一鉴权依据。
  • 未确定身份时，可提供普通公开知识服务，私密内容要求进一步确认身份。
  • 能查询某台机器，不等于能修改它；能看到任务，不等于能给执行器发送续作指令。
  • 每个后台执行节点使用范围受限的凭证，任务权限与任务本身关联。

6. 机器与项目管理

6.1 每台已接入机器知道什么

设备身份、CPU/内存/磁盘/GPU、系统版本、资源使用、服务状态、当前项目与任务、最近上报时间、备份状态和恢复方法。

每台设备可部署轻量采集组件，或通过适合的只读通道接入。项目目录由用户登记或批准发现；不默认扫描整台机器的所有文件。

建议起步时：机器心跳约每 60 秒；资源指标按负载选择 30～60 秒；任务使用事件推送，另有心跳确认连接。这些是待调优配置，不是固定性能承诺。

离线设备显示最后在线时间、最后已知项目与状态。管家区分机器失联、执行器停止、任务等待输入和无任务空闲。

6.2 项目档案

每个项目使用稳定的项目 ID，记录：

  • 仓库与项目说明、关联机器和工作目录、当前分支或 worktree。
  • 环境依赖、启动与验证方法、部署目标、配置与密钥引用。
  • 当前阶段、目标与验收条件、待办、阻塞和已知问题。
  • 相关任务、会话、提交、构建、测试、经验、Skill 和产出物。

同一项目可以存在多个工作副本，管家记录各副本的机器、分支与状态，而不是把某个本地目录当成项目唯一身份。

6.3 自动发现与明确登记结合

自动采集擅长发现进程、服务和仓库状态；它不能可靠推断所有工作的业务意图。项目目标、里程碑、敏感范围与“这次在做什么”需要明确登记或由用户确认。

可提供简短入口：“在这台机器上登记当前项目”“把这个任务关联到某项目”“结束本次开发并归档总结”。

7. 经验、问题与通用 Skill 管理

7.1 收集方式

网页或手机提交、命令入口、开发工具集成、任务结束总结、语音记录均可进入统一收件区。用户可以选择提交一段说明、日志摘录、链接、文件或已有 Skill。

公司和个人项目分别确定可上传的内容，密钥等敏感内容应在出网或共享前处理。原始记录与摘要可采用不同保存和共享范围。

7.2 整理与复用链路

问题与原始记录
    → 关联机器、项目和任务
    → 整理背景、排查、解决方法与验证结果
    → 标记适用环境，合并重复经验
    → 提炼可复用步骤
    → 形成有版本的 Skill 或 Runbook
    → 在后续任务中检索、提供并记录使用结果
内容 建议字段
问题 / 经验 来源、时间、环境、症状、原因或未确定部分、处理步骤、验证证据、适用范围
Skill 名称、用途、触发条件、前置条件、步骤、可选脚本、验证方式、版本、来源与权限要求
Runbook 运维对象、检查步骤、执行条件、变更与恢复方法、验证、所需权限
使用记录 哪个任务用了哪个版本、结果如何、是否发现新的限制

7.3 存储与发布

  • Git 保存正式的经验文档、Skill 与 Runbook，便于版本比较和追溯。
  • 业务库保存关联、状态、标签和验证记录。
  • 检索索引帮助查找，原文和正式版本仍有明确来源。
  • NAS 保存原始附件和归档，工作副本与活跃数据库使用合适的本地快速磁盘。
  • 项目经验、家庭共享知识、个人学习记录分别管理访问范围。

Skill 可处于“待整理、待验证、可用、已废弃”等状态。新提交的内容不自动成为全局规则；正式发布后按各工具的原生格式提供。项目自身的规则文件与中央 Skill 分别管理，发生冲突时按项目范围、有效版本和明确优先级处理。

8. CC / Codex 的全天监督与持续开发

8.1 全天在线的含义

管家的状态服务、事件收集和监督调度保持在线。执行节点有任务时保持运行；没有任务时可按策略休眠。模型只在需要理解、规划、总结或执行任务时调用，不必为监控而持续推理。

关掉 HP 或家庭电脑后，后台节点上的任务仍可继续；仅在该电脑上运行的任务不能因管家在线而自动继续。跨机器接续要有仓库、必要环境、工作状态和执行器可恢复条件，不能只复制一个会话 ID。

8.2 两种接入模式

模式 管家职责 范围
跟踪本人手动开启的会话 汇总可获取的工具事件、Git 变更、测试和产出，显示状态并提醒 对已有桌面或 IDE 会话的可见范围取决于版本与接入方式
管家托管任务 创建任务、选择节点、启动执行器、保存会话、验收、续作与停止 先支持通过官方 CLI / 程序接口创建的任务，再扩展其他入口

不能仅凭某工具支持程序接口，就认定管家能直接控制所有既有桌面窗口。对不支持直接接入的会话，可以先提供登记和只读证据跟踪。

8.3 官方执行器接入方向

  • Codex：非交互执行的 JSONL 事件可提供执行状态；App Server 提供会话恢复、计划、变更、执行与完成事件等接口。
  • Claude Code：结构化输出、Hooks 和会话恢复可用于记录活动与继续指定会话。
  • 两类工具都应通过各自适配器转为统一任务事件。部署时核实实际版本、认证方式、许可范围和错误处理。

依据：Codex App Server、Codex 非交互模式、Claude Code 编程接口、Claude Code Hooks。

8.4 任务创建时的必要信息

目标、项目与工作副本、验收条件、可执行范围、执行节点或资源需求、时间/费用/重试边界、停止条件、产出位置、需要用户决定的事项。

“继续开发”应对应明确的目标和待办。第一阶段结束后，监督器读取证据并决定下一步，不把“说完一轮”直接当成“项目完成”。

8.5 统一任务状态

状态 含义 监督动作
待执行 排队或等待节点可用 按优先级与资源派发，必要时唤醒节点
执行中 有有效执行活动 记录事件；避免重复派发同一任务
验证中 检查阶段产出与验收条件 运行相应验证、收集测试或构建证据
等待用户 需要明确输入或授权 告知具体缺项，收到答复后再继续依赖它的工作
等待资源 / 额度 节点、网络、登录或额度暂不可用 保留状态，按允许策略恢复；不擅自切换付费方式
阻塞 已有证据表明无法继续，或重复失败达到配置上限 整理问题、已尝试方法与建议，交给用户处理
暂停 用户主动暂停 保留恢复信息，不自动续作
已完成 明确的目标通过验收 归档成果、总结与经验；按项目计划决定是否有新的独立任务
失败 / 取消 本次执行失败或任务被取消 标记结果与可恢复信息，避免误报完成

机器离线、会话连接断开、日志暂时安静都是观察信号，需要结合心跳、工具事件和任务环境判断。长时间编译不等于卡住，提交数量也不等于有效进展。

8.6 监督闭环

明确目标与验收
    → 派发到合适节点
    → 接收事件、心跳、Git 与测试结果
    → 判断正在推进 / 等待 / 重复失败 / 阶段完成
    → 验证结果
    → 续作下一明确步骤，或请求用户处理阻塞
    → 达成目标后归档产出与经验

监督器的续作逻辑以确定性状态规则为基础，必要时调用模型总结或提出下一步。一次恢复操作、一次重试和一次新任务应有不同标识，避免在断网重连时重复执行。

8.7 工作区与人工开发协作

  • 托管任务使用独立工作目录、Git worktree 或隔离环境。
  • 同一工作副本默认只允许一个写入执行者；多人或多个执行器协作时使用明确分支和合并流程。
  • 人工接管、暂停和取消具有明确优先级，监督器不能把用户停止当成需要自动恢复的故障。
  • 任务完成证据包含适合该变更的验证、相关提交或变更、产出物与遗留事项；不要求为低影响变更无意义地重复测试。

9. 家庭聊天、学习与生活服务

9.1 日常聊天与个人记忆

提供自然交流，按使用者偏好调整回答长度、语音速度与风格。个人记忆由本人选择保存、修改和删除；不默认把所有家庭对话永久保存，也不把个人内容自动发布为共享知识。

9.2 语言陪练

目标语言与当前水平分别配置，可使用日常交流、旅行、学校、工作等情景。练习支持自由对话、重点表达、纠错、解释与复习。

学习记录保存目标、最近练习、薄弱点和复习建议。发音反馈属于需要单独实测的能力，不能仅凭普通语音转文字可靠评价所有发音细节。

9.3 历史与知识学习

按年龄和基础解释概念，结合故事、时间线、地图或小练习帮助理解。涉及事实争议时区分资料证据与解释；需要更新的知识查询实时来源。孩子的年龄与学习目标后续确认，不预设具体年级或能力。

9.4 天气、信息与烹饪

天气明确地点、预报时间与查询时间；新闻、政策、价格等会变化的信息也标记来源和时间。

做饭建议结合食材、人数、口味、饮食限制与厨具。可提供分步语音指导、计时与替代方案，饮食偏好按家人各自选择保存。

9.5 健康信息辅助

帮助整理不适表现、持续时间和相关背景，查询权威健康资料，并提示需要专业帮助的情况。回答区分一般信息与个体判断，不把不确定推测当作确诊，不自动生成并执行诊疗或用药决策。

健康信息按个人范围保存。遇到可能紧急的情况，服务应明确提示及时寻求专业医疗或急救帮助；具体回答需根据问题、所在地和可靠来源生成。

10. 网页、大屏、手机与语音

10.1 三类大屏视图

视图 主要内容 使用范围
家庭视图 天气、共同日程与待办、适合共享的信息、学习入口 家庭共享
个人管理视图 机器、项目、任务、阻塞、审批、成果、费用与资源使用 按本人或授权管理者权限
个人学习视图 练习记录、进度、复习计划与学习资料 按个人档案权限

家庭大屏默认使用适合共享的视图。进入个人管理视图需有相应身份；私密项目和健康信息不因屏幕在家里就自动公开。

10.2 管理视图要展示什么

  • 机器在线状态、资源使用、当前任务与最后上报时间。
  • 项目所处阶段、关联机器、目标和待办。
  • CC/Codex 的真实活动、当前步骤、阻塞与验证结果。
  • 待本人处理的输入、审批、登录或决策。
  • 新产出、经验和 Skill 版本。
  • 能获得的费用与用量；估算和未知分别标记。

有可衡量里程碑时展示完成比例，否则显示步骤与证据。任务详情可以追溯到机器、会话、变更、测试和产出物，不根据输出字数编造进度百分比。

10.3 同一份状态用于语音

“昨晚项目推进到哪里了？”“有哪些任务需要我处理？”“陪我练十分钟英语。”等请求由同一 Core 处理。语音识别后的系统操作仍走身份与执行权限检查。

10.4 语音落地路径

先做手机或网页按键语音，再做固定终端和连续对话，最后完善自定义唤醒词、打断与声纹档案选择。

ASR/TTS 的候选可延续 V3 的 FunASR、SenseVoice、CosyVoice 等方向，最终按中文效果、CPU/GPU 占用、延迟和兼容性实测选择。家庭主力 GPU 电脑关机时，要明确可用的 CPU 或经用户选择的云端语音路径；隐私模式不得自动绕到云端。

V2/V3 的约 1.2～2.5 秒预算只能作为“说完后到第一段有效语音”的待测目标，不能当作所有问题完整回答的时长。复杂查询和开发任务采用确认接收、后台执行、结果推送。

家庭语音终端需要合适的麦克风、扬声器、网络和权限设置。唤醒检测、音频上传与录音保存分别配置，普通会话无需持续存档环境录音。

11. 技术选型与各组件职责

11.1 起步采用轻量业务核心

层 建议方向 职责与边界
业务核心 轻量自研 Jarvis Core；FastAPI 可作为候选 身份、范围、项目与任务、状态、经验和技能关联、查询与调度
业务状态库 PostgreSQL 可作为候选 保存正式状态、事件索引、关联与任务队列；低负载起步可先用数据库队列
工作流 n8n 定时、通知、审批界面和外部流程；执行许可由 Core 验证
模型网关 New-API 或经核实满足需求的同类网关 模型路由、限额、可获得的调用记录、费用和故障处理
早期对话入口 Open WebUI 可选 快速验证聊天与知识查询；自研平台负责最终统一业务体验
工具与适配器 MCP 与受控 API 暴露能力；权限、业务校验和审计仍由服务端落实
开发执行器 Codex / Claude Code 官方 CLI 或程序接口 根据受控任务执行代码、文档与其他工作
文档与 Skill Git / Gitea 版本化原文、脚本、资源和发布记录
检索 小规模先用简单检索，规模与效果需要时引入 Qdrant 等 提供资料检索，不替代原始来源和正式记录
可观测 Uptime Kuma、基础指标；需要时加入 Prometheus/Grafana/Loki 监测、诊断与保留适量日志

不为起步同时引入所有组件。复杂队列、多执行器并发、长任务恢复或高流量出现实际需求后，再扩大实现。

11.2 Core API 的业务契约

至少覆盖身份与档案、机器和项目、任务与事件、审批、经验和技能、知识查询、家庭会话和状态摘要。入口之间通过统一契约复用能力。

模型接口是否采用 OpenAI 兼容形式，与业务 API 的职责分开。单个聊天接口不承担所有任务状态、权限和资料管理。

11.3 最小数据模型

对象 关键关联
使用者 / 家庭档案 数据范围、偏好、学习与个人记忆
机器 / 服务 硬件、环境、状态、时间、恢复信息
项目 / 工作副本 仓库、目录、分支、机器、目标和规则
任务 / 执行尝试 / 会话 项目、节点、执行器、目标、状态、预算与产出
事件 / 验证 / 产出物 来源、时间、序号或幂等标识、证据、权限范围
经验 / Skill / Runbook 来源、版本、验证、适用范围与使用记录
审批 / 变更 / 备份 对应任务与具体动作、决定、恢复信息和结果

执行节点离线时可暂存事件，恢复后按标识补交。进度汇报带最近数据时间；缺失或估算字段不伪装成确定事实。

12. 私有组网与执行接入

12.1 网络方向

以 Tailscale 等私有组网为起步方向；费用、设备限制和实际功能在部署时核实。Headscale/DERP 自建作为以后有明确需求时的选项。

公网入口仅承担必须公开的回调或分享服务，并配置身份验证、HTTPS 与必要的访问限制。日常管理界面和数据库优先在私网访问。

日本服务器可承担必要的模型访问出口，但机器心跳、原始文件和家庭数据不因统一管理而全部绕行海外。脱敏处理应在内容出网前完成，具体规则和还原方式按任务场景验证。

12.2 执行通道

Linux 可用专用账号与受限 SSH；Windows 按实际系统评估适合的采集与执行通道；容器、虚拟机、NAS、Git 和业务系统优先使用明确权限的 API。

每个自研系统适配器可提供五类能力：状态、日志、业务只读查询、运维变更、业务动作。后三类中的写入和业务控制按风险策略授权。具体 OA/EMS 接入等待真实接口资料。

13. 安全、审批、审计与停止

13.1 操作风险分级

沿用 L0～L3 的思路，但按对象、环境与影响判定，不能只根据命令名称分类。

等级 示例 默认策略
L0 在授权范围内查状态、读日志、查知识和任务 自动查询并留必要记录
L1 在独立工作区生成文档、修改代码、运行适合的验证、可恢复的整理 在任务授权范围内自动执行，记录结果
L2 部署、修改运行配置、生产服务重启、业务库写入、覆盖或删除文件 审批明确的动作；准备适合的备份或恢复方法，再执行与验证
L3 删除不可替代数据、修改关键权限、付款、实际业务控制指令 审批与可靠的二次确认，明确范围及恢复限制

生成一份测试文档与覆盖正式资料、重启测试容器与重启关键生产服务应有不同判定。

13.2 审批与执行绑定

审批对应具体任务、目标、操作内容和有效范围。待审批内容改变后重新核对授权；n8n 的按钮只是交互入口，不能独立绕过 Core 的许可检查。

急停或暂停应停止新派发，并向执行节点传递停止请求；无法瞬时安全中止的步骤记录状态并采取适合的停止方式。用户主动暂停后不自动恢复。

13.3 凭证、内容与记录

凭证使用受限账户和明确的密钥引用，存储方式按可用密钥管理能力选定。不默认认为某个密码管理工具可以直接提供所有短期凭证功能。

日志、外部资料、经验和 Skill 中的文本是来源内容，不能未经检查转为系统执行指令。记录包括请求、判断、授权、执行、验证和结果，并按个人/项目权限限制访问。

14. 存储、备份、监控与成本

14.1 存储安排

  • 活跃数据库、任务工作区和经常运行的虚拟机优先放合适的本机快速磁盘。
  • NAS 汇聚原始资料、归档与版本化备份。
  • 256GB 可起步，但要核实余量、介质、健康和写入负载。虚拟机、镜像、日志与模型文件需要明确配额和清理策略。
  • 48G 桌机、E5 和 GPU 主机的磁盘情况是扩容决策的重要依据；确认需求后再购买。

14.2 恢复职责

对象 恢复安排
i3-01/02 基础服务 版本化备份到 NAS；i3-03 定期恢复并验证
项目与完整应用 ProDesk i5 进行恢复演练和预发布验证
Git 与 Skill 版本记录加独立备份，不仅保留在线仓库
任务记录与产出物 状态库备份、附件归档、保留恢复所需映射
关键资料 在 NAS 之外保留合适的异地或离线副本

以多份副本、不同介质和异地副本为目标；只有完成实际配置与恢复演练后，才记录已达到的备份保障。NAS 内部复制、RAID 或同机快照不能覆盖整台设备损坏的情况。

14.3 监控重点

机器心跳、服务健康、磁盘余量、备份成功、任务阻塞、执行器登录/额度、GPU 资源、证书与必要的 NAS 状态。告警区分需要用户处理、可以按已授权策略处理和仅需记录的情况。

正常状态不持续打扰家人。完成、失败、需要决策和重要状态变化才推送；用户选择的晨报汇总机器、任务成果、备份与费用。

14.4 费用与功耗

区分实际 API 账单、工具能提供的用量、订阅额度以及估算费用。订阅登录与按量 API 分别管理；额度耗尽不默认转为付费调用。

CPU 的 TDP 不是整机待机功耗。对常驻 i3、NAS、GPU 主机和 E5 分别测量闲置、典型任务和满载功耗，再配置开关机策略。每增加 10W 的全年持续负载，理论上增加约 87.6kWh 用电，实际费用按当地电价计算。

15. 实施顺序与验收

阶段名称代表顺序，不承诺固定周数。家庭服务与开发管理并行验证，不必等所有机器接入后才使用。

阶段 建设内容 验收标准
S0 基础与首批入口 核实设备、私有访问、两台常驻 i3、Core 基础、身份与备份；家庭文字聊天、个人项目登记 手机可访问；不同账号只看到其范围；一个真实项目有机器与目录记录
S1 状态与经验 一张大屏、机器采集、一个 CC 或 Codex 任务接入、经验收件和检索 任务状态有来源与时间；可见测试/产出；一条经验可提交、检索和复用
S2 托管持续开发 独立工作区、持久任务队列、监督状态机、验收、有限重试、暂停与恢复 一个明确目标能持续推进到验收，或准确报告阻塞；不会重复派发，不自动恢复用户暂停
S3 家庭学习与语音 家庭档案、语言与知识学习、按键语音、大屏家庭视图；语音路线实测 家人可独立使用；学习记录按人保存；GPU 主机关闭时语音可用范围清楚
S4 扩展与主动服务 更多机器与执行器、唤醒终端、自研 API、Runbook、晨报和受控自愈 真实系统接入通过验收；重要动作有授权、记录和验证，恢复方法经过演练

15.1 第一版重点验收场景

  1. 家庭成员使用各自身份进行聊天、信息查询或简单学习。
  2. 登记一个真实个人项目，看到其所在机器、目录、当前目标与任务。
  3. 在后台节点运行一个官方执行器任务，大屏显示实际步骤、状态、阻塞和产出。
  4. 从任意已接入入口提交一条经验，整理后能够查到并关联原项目。
  5. 将一条经过验证的经验整理为可复用 Skill，后续任务能获得指定版本。
  6. 机器关机、任务暂停和数据过期时，网页与管家回答保持一致。
  7. 从备份恢复最小核心并验证项目与任务记录。

15.2 语音与硬件实测

  • 中文 ASR 的准确率、CPU/GPU 耗时、噪声环境与长辈使用效果。
  • TTS 首段延迟、音质、语速与资源占用。
  • 出网模型的首字延迟和语音首段响应。
  • 4070 上模型与感知服务的显存占用、并发和任务切换。
  • i3 的业务服务、采集与轻量任务负载，以及数据库/日志磁盘增长。
  • WOL 成功率、节点从唤醒到可执行的耗时和错误恢复。
  • 24 小时托管任务的中断、重连、额度、停止和验收行为。
