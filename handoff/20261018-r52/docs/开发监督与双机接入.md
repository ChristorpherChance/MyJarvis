# 开发监督与双机接入

更新：2026-10-09。平台主节点为 112，101 保持备用。两台新的开发机器尚未登记，真实 Codex / Claude 项目尚未进行连续运行验收。

## 已实现的监督闭环

- 在“开发监督”页查看托管任务、执行节点、执行器、用量边界和自动恢复时间；任务详情可查看实际日志、摘要、产物和验收记录。
- 开启平台监督后，派发已登记的排队任务。已完成的工作按同一项目的原生会话续接，禁止选择全局最近会话。
- 执行器明确报告尚有工作时，在批准轮数内继续。配置了固定验证程序后，真实测试失败可将输出交给下一轮修复。
- 识别额度、网络、登录、权限及未知失败。额度或网络问题按明确策略有限恢复；额度受限时可切换已授权的备选执行器。
- 切换限定同一机器、同一工作根目录，不复制到另一台机器。跨 Codex / Claude 时开启新的原生会话，传递检查点摘要并检查现有代码。
- 原生会话、执行租约、恢复时间和历史回执持久保存。平台重新启动后可恢复尚未执行的等待计划，禁止重复创建同一运行。
- 任务完成声明进入“待验收”。人工验收通过才交付；未通过验收的前置任务不会自动解锁依赖任务。

这是有边界的持续开发：不会自动发明新目标，也不会因为没有输出就重启编译。审批、人工暂停、急停、预算、截止时间、工作目录、权限和资源门禁继续生效。

## 两台机器如何安排

建议每台机器安装 Codex 和 Claude Code，任选一种作为主执行器，另一种作为额度受限后的备选。每个项目登记明确目标、验收条件、非生产工作副本及预算。两台机器可并行处理不同项目；同一个项目保留单一活动任务。

已经在桌面应用中运行的项目，先记录为观察任务，收集明确授权的进度摘要。移交给贾维斯托管时，登记项目目录、当前进度和明确原生会话标识；下一轮会核对已有文件。托管不通过任意模拟键盘控制桌面聊天，也不使用 `--last` 或 `--continue`。

## 通用接入包

包内包含独立节点程序、子进程监督程序、准备工具和本文；不包含模型密钥、配对票据或家庭数据。Windows / Linux 使用同一份包，需要 Node.js 24 或以上。模型账号在开发机器上自行登录。

1. 在平台“设备管理”登记机器，在“项目管理”登记非生产副本。记下真实设备 ID。
2. 在目标机器安装 Node.js、Codex / Claude Code，先手动确认能够开发并运行项目测试。
3. 解压接入包，检查安装和登录状态：

```text
node prepare-development-node.mjs --doctor
```

4. 生成配置。项目父目录必须已存在；实际项目放在其子目录中。订阅账号示例：

```text
node prepare-development-node.mjs --machine-id 平台设备ID --workspace-root D:\JarvisProjects --output D:\JarvisNode\agent.json --billing subscription
```

Linux 对应使用 `/srv/jarvis-projects` 和 `/home/运行账户/jarvis-node/agent.json` 等实际绝对路径。API 计费账号将 `subscription` 改为 `priced`。默认使用原生 CLI 已配置的模型；可显式传入 `--codex-model` / `--claude-model`，模型名必须是该账号实际可用的。

准备工具会同时生成 `agent.json.central-templates.json`。在“运行引擎 → 节点执行”导入这个公共模板文件，核对后确认合并到编辑区，再保存执行配置；其他设备、探测和唤醒设置保留。不要导入已配对的私有 agent.json。Windows 的 `.cmd` 入口不能直接执行，工具优先寻找原生 exe 或 Node.js 加官方 CLI 的 js 入口；找不到时可填写 `--codex-path` / `--claude-path`。

5. 在平台为这台设备生成一次性节点票据，能力填写本机模板 ID（准备工具会显示）。将票据加入本机 `agent.json` 的 `pairingTicket` 字段，5 分钟内启动：

```text
node jarvis-node.mjs --config D:\JarvisNode\agent.json
```

首次配对生成本机签名密钥并删除配置中的票据。Linux 文件权限为 0600；Windows 保存时限制给运行账户与 SYSTEM。请勿把生成后的私有配置上传代码仓库或聊天。

6. 确认节点心跳和执行器可用；先启动一个小任务验证实际文件修改、日志、固定测试、暂停、续接及费用，再开启持续监督。后台长期运行应使用该机器的常驻服务；首次接入由实际系统决定 Windows 任务或 Linux 服务，不在未登记机器上自动安装。

## 续轮、切换与计费配置

“开发监督 → 持续策略”可设置每次最多轮数、整个任务 Token 边界、恢复次数、等待时间、测试修复及本机备选执行器。导出模板后同步到节点配置并重启节点；中央和节点的执行程序、参数及策略必须一致，配置漂移会拒绝执行并提示处理。

- 订阅账号：明确选择 `subscription`，用轮次、单轮时限及 Token 边界限制续轮。未知美元费用仍显示未定价，不记成零元。
- API 计费：选择 `priced`。Codex 未提供可核算金额时停止续轮；可填写与实际模型匹配的输入、输出每百万 Token 单价，金额注明目录估算。
- Claude 的 `total_cost_usd` 是原生整个会话的累计客户端估算。平台保存匹配会话的检查点，只追加差额；缺少续接基线或累计值回退时显示未定价，避免重复扣费。
- 默认恢复建议：最多 3 次，等待 900 秒。两类执行器都近期额度受限时等待原执行器，避免来回切换。没有可用备选则等待，不保证替代账号一定有额度。
- Token 边界在每轮结束后检查，可能超出一轮用量，不能承诺实时硬限额。USD 目录估算也不能代替供应商账单；最终以实际账单为准。

固定验证程序由管理员配置，例如使用 Node.js 的绝对路径执行本项目测试脚本；不接受模型输出的任意 shell 命令。Claude 使用其本机原生项目权限，工作目录约束不代替操作系统沙箱。建议用独立开发账户和非生产副本。

## 哪些情况会停下来

登录失效、权限不足、未知错误、固定验证未通过且修复轮次耗尽、恢复次数耗尽、预算或截止时间到达，都进入待处理或阻塞状态。节点离线、进程崩溃导致租约过期时暂停任务，由管理员核对文件和用量后恢复，避免重复执行已修改的代码。

关闭监督停止自动续轮和自动恢复，手动任务仍可执行一轮；急停取消受控任务。候选代码成功后不会自动发布生产服务。任务暂停或取消后仍保留日志、用量和产物。

## 验收现状

已用隔离进程和真实签名节点协议验证：明确会话续接、固定测试失败修复、累计费用差额、额度受限切换、恢复次数限制、策略撤销、截止时间、急停、用量缺失和本地配置漂移。测试中使用原生格式的模拟 CLI，没有消耗两台待安装机器的模型账号。

真实机器、具体操作系统、账号登录、项目目录和固定测试入口仍需接入确认；这些完成后，进行真实项目至少一轮开发、一次续接、一次受限恢复的验收。

官方接口依据：[Codex 非交互执行](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude Code 非交互执行](https://code.claude.com/docs/en/headless)。
